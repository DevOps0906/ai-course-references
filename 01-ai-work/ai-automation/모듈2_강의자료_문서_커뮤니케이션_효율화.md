# 2-1. 보고서·기획안·매뉴얼 자동화 프롬프트 패턴 (1H)

## 1. 왜 '패턴'인가 — 문서마다 공식이 다릅니다

모듈 1에서 배운 R-C-T-F-C(역·맥·지·형·조)는 **만능 뼈대**였습니다.
이제 여기에 **문서 유형별 공식(패턴)** 을 끼워 넣으면, 매번 고민하지 않고 초안이 나옵니다.

대학 행정 문서의 4대 유형과 각각의 '급소':

| 문서 유형 | 이 문서의 존재 이유 | 급소 (여기가 좋아야 통과) |
|---|---|---|
| 결과보고서 | "했습니다 + 이만큼 성과가 났습니다" | 숫자로 말하는 성과, 간결한 개조식 |
| 기획안 | "이걸 하게 해주세요(예산/승인)" | 목적의 설득력, 기대효과 |
| 업무 매뉴얼 | "내가 없어도 누구나 할 수 있게" | 빠짐없는 단계, 예외상황 안내 |
| 공문·안내문 | "정확히 전달하고 행동하게 하기" | 일시·장소·방법의 명확성, 격식 |

### ✏️ 빈칸 채우기 ⑧ — 문서의 급소 찾기

> 1. 기획안에서 결재권자가 가장 먼저 보는 것은 "왜 하는가"와 "**( ㄱ )**"다.
> 2. 결과보고서의 성과는 형용사("성황리에")보다 **( ㄴ )** 로 표현해야 설득력이 있다.
> 3. 업무 매뉴얼은 작성자 기준이 아니라 **( ㄷ )** 기준으로, 모든 단계를 빠짐없이 써야 한다.

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) 기대효과(무엇이 좋아지는가)** — 예산과 승인은 결국 "투자 대비 효과"로 결정됩니다.
- **( ㄴ ) 숫자(정량 지표)** — "성황리에 종료" ❌ → "참여 152명, 목표 대비 121%, 만족도 4.6/5.0" ⭕
- **( ㄷ ) 처음 하는 사람(신입/후임자)** — "로그인한다" 한 줄도 신입에게는 "어디에? 어떤 계정으로?"가 필요합니다.

💡 이 '급소'를 프롬프트의 **[조건]** 에 넣는 것이 오늘 배울 패턴의 핵심입니다.
</details>

## 2. 패턴 ① 결과보고서 — "숫자 먼저, 개조식으로"

### 💻 [따라하기 6] 결과보고서 초안 만들기

아래는 실습용 가상 데이터입니다. 프롬프트 전체를 그대로 복사해 입력하세요.

```
[역할] 너는 대학 행정 문서 작성 15년차 교직원이야.
[맥락] 아래 [메모]는 지난주 종료된 "재학생 AI 리터러시 특강" 운영 결과 기록이야.
[지시] 결재용 결과보고서 초안을 작성해줘.
[형식] 1.개요(목적·일시·장소·대상) / 2.추진 내용 / 3.운영 결과(정량 성과 표) /
      4.만족도 및 주요 의견 / 5.성과 및 개선점 / 6.향후 계획 순서.
[조건] - 전체 개조식 문장(~함, ~임)으로. "성황리에" 같은 수식어 대신 숫자로 표현
      - 성과는 목표 대비 달성률(%)을 계산해서 표에 포함
      - A4 1장 분량

[메모]
- 특강명: 재학생 AI 리터러시 특강 / 5월 14일(수) 14~16시 / 대강당
- 목표 인원 120명, 실제 참석 152명
- 강사 1명(외부), 내용: 생성형 AI 소개와 리포트 작성 활용법
- 만족도 설문 138명 응답, 평균 4.6/5.0
- 주요 의견: "실습 시간 부족"(31건), "정기 개설 희망"(24건)
- 예산: 계획 80만원, 집행 76만원
```

**관찰 포인트**: ① 달성률 126.7%를 AI가 알아서 계산했는지 ② 개조식이 지켜졌는지 확인하세요. 틀렸다면? → 수정 지시: `"3번 표에 목표/실적/달성률 열을 넣어 다시 만들어줘."`

📌 **핵심정리**: **원자료(메모·엑셀 요약)를 [자료] 블록으로 던져주는 것**이 보고서 자동화의 90%입니다. AI는 백지에서보다 자료를 '재구성'할 때 훨씬 정확합니다.

## 3. 패턴 ② 기획안 — "설득의 구조를 미리 주기"

기획안 만능 골격: **배경 → 목적 → 추진 내용 → 일정 → 예산 → 기대효과**

### 💻 [따라하기 7] 기획안 초안 + 예상 반박 뽑기

```
[역할] 너는 대학 교육혁신 기획 전문가야.
[맥락] 우리 부서는 2학기에 "교직원 대상 AI 업무 자동화 심화 과정(월 1회, 총 4회)"을
      새로 개설하려고 해. 1학기 기초 과정 만족도가 4.6점으로 높았던 것이 근거야.
[지시] 결재용 기획안 초안을 작성해줘.
[형식] 1.추진 배경 / 2.목적 / 3.추진 내용(회차별 주제 표) / 4.일정 / 5.소요 예산(항목별) / 6.기대효과
[조건] 개조식, A4 1장. 기대효과는 정량(시간 절감)과 정성(역량 강화)으로 나눠서.
```

**STEP 2. (기획안 패턴의 필살기)** 초안이 나오면 이어서 입력:

```
좋아. 이제 결재권자 입장에서 이 기획안에 나올 수 있는 예상 질문·반박 5가지와
각각에 대한 답변을 준비해줘.
```

📌 **핵심정리**: AI에게 **"반대편 역할"** 을 시키는 것 — 기획 업무에서 가장 저평가된 활용법입니다. 결재 들어가기 전 예상 질문을 미리 막을 수 있습니다.

## 4. 패턴 ③ 업무 매뉴얼 — "인수인계 5분 컷"

### 💻 [따라하기 8] 머릿속 지식을 매뉴얼로 꺼내기

매뉴얼의 최대 난관은 "내가 아는 걸 글로 옮기기 귀찮다"는 것. **AI에게 인터뷰를 시키세요.**

**STEP 1.**

```
나는 "외부 강사 초빙 행정 절차" 매뉴얼을 만들려고 해. 너가 인수받는 후임자라고
생각하고, 매뉴얼 작성에 필요한 질문을 나에게 하나씩 해줘. 내가 답하면
다음 질문으로 넘어가고, 질문이 끝나면 답변을 종합해서 매뉴얼 초안을 만들어줘.
```

**STEP 2.** AI의 질문("강사 섭외는 언제까지?", "결재 라인은?")에 **말하듯 편하게** 답하세요. 5~7개 질문 후:

**STEP 3.**

```
이제 지금까지 내 답변을 종합해서 업무 매뉴얼로 정리해줘.
[형식] 1.업무 개요 / 2.단계별 절차(단계·할 일·기한·담당/결재·유의사항 표) /
      3.자주 발생하는 예외상황과 대처 / 4.관련 서식·시스템 목록
[조건] 처음 하는 사람이 이 문서만 보고 처리할 수 있는 수준으로 구체적으로.
```

# 2-2. 회의록 요약·액션아이템 추출 및 이메일·메신저 응답 템플릿 

## 1. 회의록 — "1시간 회의, 5분 정리"

회의록 업무의 본질은 받아쓰기가 아니라 **구조화**입니다: 무슨 얘기가 오갔고(논의) → 뭘 하기로 했고(결정) → 누가 언제까지 하는가(액션아이템).

### 💻 [따라하기 9] 지저분한 메모 → 공식 회의록

아래 실습용 가상 녹취 메모를 프롬프트와 함께 통째로 입력하세요.

```
[역할] 너는 대학 행정 회의록 작성 전문가야.
[맥락] 아래 [메모]는 학과 사무실에서 열린 "2학기 신입생 오리엔테이션 준비회의"의
      녹취 메모야. 말한 순서 그대로라 정리가 안 되어 있어.
[지시] 공식 회의록으로 정리해줘.
[형식] 1.회의 개요(일시·장소·참석자) / 2.안건별 [논의내용/결정사항] 표 /
      3.액션아이템 표(할 일·담당·기한) / 4.차기 회의 일정
[조건] - 개인적 잡담·중복 발언은 제외
      - 결정된 것과 논의만 된 것을 명확히 구분 (결정 안 된 건 "추후 논의"로 표기)
      - 개조식

[메모]
8/12 오후 2시 학과 회의실. 참석: 김팀장, 박선생, 이선생, 최조교
김팀장: OT 날짜 3/2 확정된 거죠? 박: 네 대강당 예약 완료했습니다.
이: 기념품은 작년에 텀블러였는데 올해는 에코백 어떨까요. 김: 견적 받아봅시다.
박: 아 그리고 작년에 주차 안내가 없어서 민원 많았어요. 올해는 안내문에 꼭 넣죠. (모두 동의)
최: 학생증 발급 부스는 작년처럼 로비에 두면 되나요? 김: 네 그대로 갑시다.
이: 점심 도시락 업체는 두 군데 비교 중인데 다음 주까지 정할게요.
김: 그럼 기념품 견적은 이선생님이 금요일까지, 안내문 초안은 최조교가 다음 회의 전까지.
다음 회의는 8/19 같은 시간.
```

**관찰 포인트**:
- "에코백"이 **결정사항**으로 잘못 들어가지 않았는지 확인하세요. (견적만 받기로 했지 결정된 게 아닙니다!)
- 액션아이템 표에 담당·기한이 정확히 매칭됐는지 확인하세요.

→ 틀렸다면 수정 지시: `"기념품 변경은 결정사항이 아니라 '견적 검토 후 추후 논의'야. 수정해줘."`

📌 **핵심정리**: 회의록에서 사람이 반드시 검수할 곳은 단 두 군데 — **결정사항의 진위**와 **담당자·기한**. 나머지 형식은 AI에게 맡기세요.

### ✏️ 빈칸 채우기 ⑩

> 회의록 프롬프트의 3대 필수 요소:
> ① 논의내용과 **( ㄱ )** 을 구분하라는 조건
> ② 할 일·**( ㄴ )**·**( ㄷ )** 3열로 된 액션아이템 표
> ③ 잡담·중복 발언 **( ㄹ )** 조건

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) 결정사항** — 이걸 구분 안 하면 "논의만 된 것"이 "확정"처럼 기록되는 대형 사고가 납니다.
- **( ㄴ ) 담당(자)** / **( ㄷ ) 기한** — 담당과 기한 없는 액션아이템은 아무도 안 하는 일이 됩니다.
- **( ㄹ ) 제외** — 조건을 안 주면 AI는 잡담까지 성실하게 기록합니다. 😅
</details>

## 2. 장문 요약 — "다 읽지 말고, 골라 읽기"

긴 공문·지침·논문을 받았을 때 그대로 쓰는 요약 프롬프트:

```
아래 문서를 다음 3단으로 요약해줘.
① 3줄 핵심 요약
② 우리 부서가 해야 할 일 (기한이 있으면 기한 포함)
③ 놓치면 안 되는 주의사항·불이익 조항
[문서 붙여넣기]
```

📌 그냥 "요약해줘"보다 **"내가 알아야 할 관점(해야 할 일, 기한, 불이익)"을 지정**하는 것이 실무 요약의 기술입니다.

## 3. 이메일 답장 — 상황별 '톤 조절' 기술

이메일에서 어려운 건 내용이 아니라 **톤**입니다. 특히 거절·독촉·사과. AI에게 톤을 지정하는 3요소:

**관계(누구에게) × 목적(무엇을) × 온도(어느 강도로)**

### 💻 [따라하기 10] 가장 어려운 메일 — 정중한 거절

```
[역할] 너는 대학 대외협력 담당 직원이야.
[맥락] 외부 업체가 "교내 학생 대상 금융상품 홍보 부스 설치"를 요청하는 메일을 보냈어.
      학교 규정상 상업적 홍보 부스는 허가할 수 없어. 다만 이 업체는 우리 대학
      산학협력 파트너라 관계는 유지해야 해.
[지시] 거절 답장 메일을 작성해줘.
[형식] 제목 포함, 3~4문단.
[조건] - 거절 사유는 "학교 규정"으로 명확하게, 단 규정 조항 번호는 지어내지 말 것
      - 관계 유지를 위해 대안(취업설명회 등 비상업적 협력) 1가지를 제안
      - 정중하지만 재고 여지를 남기지 않는 단호한 마무리
```

**STEP 2. 온도 조절 실험** — 이어서 입력해 보세요:

```
같은 내용을 ①더 부드럽게(관계 최우선) ②더 단호하게(재발 방지 최우선) 두 버전으로 다시 써줘.
```

→ 세 버전을 비교하면 **"온도"라는 게 무엇인지** 감이 옵니다. 실무에선 상황 봐서 골라 쓰면 됩니다.

**상황별 답장 프롬프트 한 줄 씨앗** 📋 (앞에 상황만 붙여서 사용)

```
- 승인/수락: "흔쾌히 수락하되, 우리 쪽 조건(일정/범위)을 명확히 못박는 답장"
- 문의 회신: "질문에 번호 붙여 하나씩 답하고, 관련 링크·담당자 안내로 마무리"
- 독촉(1차): "상대가 잊었을 수 있다는 전제로, 기한과 필요한 것만 담백하게 리마인드"
- 독촉(2차): "미제출 시 발생하는 영향(일정 지연 등)을 언급해 부드럽지만 무게 있게"
- 사과: "변명 없이 사실 인정 → 원인 → 재발 방지 → 보완 조치 순서로"
```

### ✏️ 빈칸 채우기 ⑪ — 이 메일, 뭐가 문제일까?

어느 직원이 AI에게 이렇게 시켰습니다: `"업체에 거절 메일 써줘"`
그랬더니 AI가 **"본교 규정 제12조 3항에 의거하여"** 라는 문장을 만들어냈습니다.

> 문제점: 실제로 그런 조항이 있는지 확인되지 않았는데 AI가 만들어낸 것으로,
> 모듈 1에서 배운 **( ㄱ )** 현상이다.
> 예방법: 프롬프트 조건에 "**( ㄴ )**"라고 미리 지시하거나, 발송 전 원문 규정을 **( ㄷ )** 한다.

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) 환각(할루시네이션)** — 조항 번호, 날짜, 인명, 통계는 환각 최다 발생 지점입니다.
- **( ㄴ ) "규정 조항 번호는 지어내지 말 것" (또는 "모르는 정보는 [확인 필요]로 표시할 것")** — [따라하기 10] 조건에 이미 넣어둔 이유입니다.
- **( ㄷ ) 검증(확인)** — 외부 발송 문서는 특히! 메일은 취소가 안 됩니다. 📮
</details>

## 4. 메신저 템플릿과 FAQ화 — "같은 질문, 두 번 타이핑하지 않기"

### 💻 [따라하기 11] 자주 받는 질문 → 표준 답변 세트

**STEP 1.** 내가 자주 받는 질문 3~5개를 떠올려 그대로 나열해 입력하세요. (예시 그대로 실습해도 됩니다)

```
나는 대학 학사 담당 직원이야. 아래는 학생들에게 반복해서 받는 질문이야.
각 질문에 대한 표준 답변을 만들어줘.
[형식] 질문별로 ①카카오톡용(2~3문장, 친근한 존댓말, 이모지 1개)
      ②이메일용(격식체, 상세 안내) 두 버전씩.
[조건] 날짜·링크처럼 매번 바뀌는 정보는 [날짜], [링크] 자리표시자로 비워둘 것.

[자주 받는 질문]
1. 재학증명서 어디서 떼요?
2. 수강 정정 기간 언제까지예요?
3. 휴학 신청 절차가 어떻게 되나요?
```

**STEP 2.** 결과를 메모장/노션에 저장 → **[날짜], [링크]만 바꿔서 평생 재사용.**

📌 **핵심정리**: **자리표시자([날짜], [담당자]) 지시**가 템플릿화의 핵심 기술입니다. 이 감각은 모듈 3-2(반복 보고서 템플릿)에서 그대로 확장됩니다.
