# 1-1. AI·생성형AI 개념 및 트렌드 

## 1. AI, 도대체 뭐가 뭔지부터 정리합시다

용어가 너무 많아서 헷갈리시죠? 러시아 인형(마트료시카)처럼 **큰 개념 안에 작은 개념**이 들어있다고 생각하면 쉽습니다.

```
인공지능 (AI)  ─ 사람처럼 판단하는 기술 전체
 └─ 머신러닝 (ML)  ─ 데이터로 스스로 규칙을 학습
     └─ 딥러닝 (DL)  ─ 인공신경망으로 학습 (사람 뇌 구조 모방)
         └─ 생성형 AI (Generative AI)  ─ 새로운 콘텐츠(글·그림·표)를 "만들어내는" AI
             └─ LLM (거대언어모델)  ─ 글을 읽고 쓰는 생성형 AI (ChatGPT, Claude 등)
```

참고 링크

- [머신러닝 vs 딥러닝](https://playground.tensorflow.org)
- [LLM 내부구조](https://poloclub.github.io/transformer-explainer)


**한 줄 정의**

| 용어 | 한 줄 정의 | 비유 |
|---|---|---|
| AI | 사람의 지적 활동을 흉내 내는 기술 전체 | "전자제품" 전체 |
| 머신러닝 | 데이터를 주면 스스로 패턴을 찾아 학습 | 문제집을 많이 풀어 요령을 터득한 학생 |
| 생성형 AI | 학습한 것을 바탕으로 **새로운 결과물을 생성** | 요령을 터득해 **직접 답안을 써내는** 학생 |
| LLM | 글(언어)에 특화된 생성형 AI | 국어·논술 만점 학생 |

### ✏️ 빈칸 채우기 ①

> 기존의 AI(예: 스팸메일 분류)는 주어진 것을 **( ㄱ )** 하는 데 강했다면,
> 생성형 AI는 새로운 글·이미지·표를 **( ㄴ )** 하는 데 강하다.
> ChatGPT, Claude처럼 글을 다루는 생성형 AI를 **( ㄷ )** (거대언어모델)이라고 부른다.

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) 분류(판별/인식)** — 기존 AI는 "이 메일이 스팸인가 아닌가", "이 사진이 고양이인가"처럼 **골라내는 일**을 했습니다.
- **( ㄴ ) 생성** — 생성형 AI는 정답을 고르는 게 아니라 **없던 결과물을 새로 만들어냅니다.** 그래서 이름이 '생성형'입니다.
- **( ㄷ ) LLM** — Large Language Model. "거대한 양의 글을 학습한 언어 모델"이라는 뜻입니다.

💡 **왜 중요한가?** 우리가 이번 과정에서 배우는 것은 전부 "생성" 능력을 업무에 활용하는 방법입니다. 보고서 초안 생성, 회의록 생성, 답장 생성 — 전부 '생성'입니다.
</details>

## 3. 생성형 AI vs RPA vs 워크플로 자동화 — 뭐가 다른가요?

자동화 이야기를 하면 이 세 가지가 항상 같이 나옵니다. **성격이 완전히 다릅니다.**

| 구분 | 생성형 AI | RPA | 워크플로 자동화 |
|---|---|---|---|
| 한 줄 정의 | 콘텐츠를 **만들어주는** 두뇌 | 사람의 마우스·키보드 조작을 **그대로 반복**하는 로봇 | "A가 일어나면 B를 하라"고 **서비스끼리 연결**하는 배관 |
| 잘하는 일 | 글쓰기, 요약, 분류, 아이디어 | 정해진 화면 클릭, 복사·붙여넣기 반복 | 폼 제출 → 시트 기록 → 메일 발송 연결 |
| 못하는 일 | 매번 같은 결과 보장 (조금씩 다르게 나옴) | 예외 상황, 판단이 필요한 일 | 콘텐츠 생성 (내용은 못 만듦) |
| 대표 도구 | ChatGPT, Claude | UiPath, Power Automate Desktop | Zapier, Make, Power Automate |
| 비유 | **작가** | **공장 로봇팔** | **컨베이어 벨트** |

**비유로 이해하기 — 김치공장에 빗대면:**
- 워크플로 자동화 = 배추가 들어오면 세척기 → 절임기 → 포장기로 **자동으로 넘겨주는 컨베이어 벨트**
- RPA = 정해진 위치에서 정해진 동작만 **정확히 반복하는 로봇팔**
- 생성형 AI = "이번 김치 신제품 이름과 홍보문구를 지어줘"라고 시킬 수 있는 **기획자**

> 1. 매일 아침 학사시스템에 로그인해 같은 화면에서 출결 데이터를 내려받는 일 → **(      )**
> 2. 수요조사 결과를 보고 "설문 응답 요약 보고서 초안"을 쓰는 일 → **(      )**
> 3. 구글폼으로 행사 신청이 들어오면 자동으로 시트에 기록되고 담당자에게 알림이 가는 일 → **(      )**
> 4. 접수된 민원 메일의 내용을 읽고 유형을 분류한 뒤 답변 초안을 만드는 일 → **(      )**

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

1. **RPA** — "같은 화면, 같은 클릭의 반복"은 RPA의 전형적인 영역입니다.

💡 **왜 중요한가?** 내 업무를 자동화하려면 "이 일은 어떤 성격인가"를 먼저 판단해야 올바른 도구를 고를 수 있습니다. 1-3에서 직접 해봅니다.

## 5. 반드시 알아야 할 유의사항 3가지

### ① 환각(할루시네이션) — AI는 모르는 것도 아는 척합니다
AI는 "그럴듯한 다음 단어"를 예측하는 기계라서, **틀린 내용을 자신 있게** 말할 수 있습니다.
- 대응법: **사실 확인이 필요한 정보(법령, 규정, 숫자, 인명)는 반드시 원본으로 검증**합니다. AI는 "초안 작성자"이지 "결재권자"가 아닙니다.

### ② 보안·개인정보 — 입력창은 외부 서버입니다
- **학생 개인정보(이름, 학번, 연락처, 성적), 내부 기밀문서를 그대로 붙여넣지 않습니다.**
- 대응법: 홍길동 → "학생A", 실제 학번 → "20XX1234"처럼 **가명화(마스킹) 후 입력**하고, 결과물에서 다시 치환합니다.

### ③ 최종 책임은 사람에게 — AI 산출물은 항상 '초안'
- 결과물은 반드시 사람이 검토·수정 후 사용합니다. "AI가 그렇게 썼는데요"는 사유가 되지 않습니다. 😅

### ✏️ 빈칸 채우기 ③

> AI가 사실이 아닌 내용을 그럴듯하게 지어내는 현상을 **( ㄱ )** 이라고 한다.
> 학생 개인정보는 입력 전에 반드시 **( ㄴ )** 처리를 해야 하며,
> AI의 결과물은 언제나 **( ㄷ )** 으로 취급하고 사람이 최종 검토해야 한다.

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) 환각(할루시네이션)** — 특히 "출처, 통계, 규정 조항"을 물으면 지어내는 경우가 많습니다.
- **( ㄴ ) 가명화(마스킹/비식별)** — 이름·학번·연락처를 기호로 바꿔 입력하는 습관을 들이세요.
- **( ㄷ ) 초안(draft)** — 이 세 가지만 지키면, AI는 가장 성실한 신입 조교가 됩니다.
</details>

# 1-2. 프롬프트 기초와 실무 지시 구조 

## 1. 프롬프트란? — "신입 조교에게 일 시키기"

**프롬프트(Prompt)** = AI에게 입력하는 지시문.

AI는 **"아주 똑똑하지만, 우리 학교 사정은 하나도 모르는 신입 조교"** 입니다.
신입에게 일을 시킬 때를 떠올려 보세요. 이렇게 시키면 어떻게 될까요?

> ❌ "행사 안내문 좀 써줘."

신입은 어떤 행사인지, 누구에게 보내는지, 언제까지인지 몰라서 **아무거나** 써옵니다. AI도 똑같습니다.

## 2. 프롬프트의 5요소: R-C-T-F-C

좋은 지시에는 5가지 요소가 들어갑니다. **"역-맥-지-형-조"** 로 외웁시다.

| 요소 | 영어 | 뜻 | 예시 |
|---|---|---|---|
| **R** 역할 | Role | AI에게 입힐 옷 | "너는 대학 행정 경력 10년의 교직원이야" |
| **C** 맥락 | Context | 배경 상황 | "우리 대학은 신입생 오리엔테이션을 3월 2일에 개최해" |
| **T** 지시 | Task | 시킬 일 (동사!) | "학생용 안내문을 작성해줘" |
| **F** 형식 | Format | 결과물의 모양 | "제목 + 인사말 + 일시/장소 표 + 유의사항 3가지로" |
| **C** 조건 | Constraint | 제한 사항 | "300자 이내, 존댓말, 이모지 사용 금지" |

### 💻 [따라하기 1] 나쁜 프롬프트 vs 좋은 프롬프트

**STEP 1.** 아래 프롬프트를 그대로 입력해 보세요.

```
행사 안내문 써줘
```

→ 결과를 관찰하세요. 어떤 행사인지도 모르는 채 일반적인 안내문이 나옵니다.

**STEP 2.** 이번에는 아래 프롬프트를 그대로 입력해 보세요.

```
[역할] 너는 대학 행정 경력 10년차 교직원이야.
[맥락] 우리 기관(디지털노마드연구소)은 3월 2일(월) 10시, 대강당에서
       신입생 오리엔테이션을 개최해. 대상은 신입생 전원이고,
       학생증 발급을 위해 신분증을 지참해야 해.
[지시] 신입생에게 보낼 안내문을 작성해줘.
[형식] 제목 / 인사말(2문장) / 일시·장소·준비물 표 / 유의사항 3가지 순서로.
[조건] 전체 400자 이내, 친근하지만 공손한 존댓말, 이모지는 1~2개만.
```

**STEP 3.** 두 결과를 비교해 보세요. 같은 AI인데 결과가 완전히 다르죠?

📌 **핵심정리**: AI의 성능 차이보다 **지시의 구체성 차이**가 결과를 좌우합니다.

### ✏️ 빈칸 채우기 ④ — R-C-T-F-C 요소 찾기

다음 프롬프트에서 각 문장이 5요소 중 무엇에 해당하는지 적어보세요.

> "너는 회의록 작성 전문가야. **(  1  )**
> 아래는 어제 학과장 회의 녹취 메모야. **(  2  )**
> 이것을 공식 회의록으로 정리해줘. **(  3  )**
> 안건별로 [논의내용/결정사항/후속조치] 표로 만들어줘. **(  4  )**
> 개인 의견 발언자 이름은 빼고, A4 한 장 분량으로. **(  5  )**"

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

1. **역할(R)** — "~전문가야"는 전형적인 역할 부여.
2. **맥락(C)** — 자료의 출처와 배경 설명.
3. **지시(T)** — 핵심 동사: "정리해줘".
4. **형식(F)** — 결과물의 구조(표, 항목)를 지정.
5. **조건(C)** — 제외할 것 + 분량 제한.

💡 다섯 요소를 매번 다 쓸 필요는 없습니다. 하지만 **결과가 마음에 안 들 때 "어떤 요소가 빠졌지?"라고 점검하는 체크리스트**로 쓰면 강력합니다.
</details>

## 3. 실무 기법 3가지 — 이것만 알면 중급자

### 기법 ① 예시 주기 (Few-shot): "이런 식으로 써줘"

말로 설명하기 어려운 스타일은 **예시를 1~2개 보여주는 게** 빠릅니다.

### 💻 [따라하기 2] 우리 부서 말투 학습시키기


# 1-3. 업무 프로세스 맵핑·자동화 후보 도출 및 기획서(AS-IS/TO-BE) 초안 작성 (1H)

## 1. 왜 '내 업무 진단'부터 해야 하나

도구를 배워도 **"어디에 쓸지"** 모르면 3일 뒤 원래 방식으로 돌아갑니다.
이 시간에는 내 업무를 **분해 → 진단 → 기획서**로 만드는 과정을 직접 해봅니다.

## 2. 업무 분해: 입력 → 처리 → 산출

모든 업무는 3단계로 쪼갤 수 있습니다.

| 단계 | 질문 | 예: "월간 프로그램 결과보고" |
|---|---|---|
| 입력 | 무엇을 받아서 시작하나? | 부서별 실적 엑셀, 사진, 만족도 설문 |
| 처리 | 무엇을 하나? | 집계, 요약, 보고서 양식에 옮겨 적기 |
| 산출 | 무엇이 나오나? | 결재용 보고서(한글/워드) |

### 💻 [따라하기 4] AI에게 내 업무 분해를 도와달라고 하기

내 업무를 어떻게 쪼개야 할지 막막하면, 그것도 AI에게 시키면 됩니다.

```
나는 대학 교직원이야. 내 업무 중 하나는 "매월 학과별 프로그램 실적을 취합해서
결과보고서를 만드는 일"이야. 이 업무를 [입력→처리→산출] 단계로 잘게 분해하고,
각 단계에서 반복적·수작업으로 하는 일이 무엇일지 추정해서 표로 정리해줘.
그리고 각 단계별로 생성형 AI가 도와줄 수 있는 부분을 제안해줘.
```

→ 표가 나오면, **틀린 부분을 수정 지시로 고치세요.** ("2단계는 실제로는 메일로 취합해. 반영해서 다시.")

## 3. 자동화 후보 고르기: 4가지 기준

모든 업무가 자동화 대상은 아닙니다. **점수가 높은 것부터** 시작하세요.

| 기준 | 질문 | 점수(1~5) |
|---|---|---|
| ① 반복성 | 얼마나 자주 반복되나? (매일=5, 연1회=1) | |
| ② 규칙성 | 매번 같은 절차·양식인가? | |
| ③ 소요시간 | 한 번에 오래 걸리나? | |
| ④ 데이터 형태 | 글·표·엑셀 등 디지털인가? (종이·대면=낮음) | |

**합계 14점 이상 = 1순위 자동화 후보!**

### ✏️ 빈칸 채우기 ⑥ — 자동화 후보 판별

다음 중 자동화 효과가 **가장 큰** 업무는 무엇일까요? 이유도 생각해 보세요.

> A. 연 1회 열리는 총장배 체육대회의 개회사 작성
> B. 매주 반복되는 주간 업무보고 작성 (지난주 실적 엑셀 → 정해진 양식)
> C. 학생과의 대면 진로 상담
> D. 5년에 한 번 하는 기관 평가 자료 준비

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

**정답: B**

| 기준 | A 개회사 | **B 주간보고** | C 대면상담 | D 기관평가 |
|---|---|---|---|---|
| 반복성 | 1 (연1회) | **5 (매주)** | 5 | 1 |
| 규칙성 | 3 | **5 (같은 양식)** | 1 (매번 다름) | 2 |
| 소요시간 | 2 | **4** | 3 | 5 |
| 데이터 형태 | 4 | **5 (엑셀)** | 1 (대면) | 3 |
| 합계 | 10 | **19** | 10 | 11 |

- **B**는 4개 기준 모두 높음 → 자동화 1순위. (참고로 모듈 3-2에서 정확히 이런 업무를 템플릿화합니다!)
- **A**는 AI로 초안을 쓸 수는 있지만 연 1회라 "자동화"보다는 "단발 활용" 대상.
- **C**는 사람이 해야 하는 일 — 자동화하면 안 되는 영역도 분명히 있습니다.
- **D**는 시간은 오래 걸리지만 반복성·규칙성이 낮아 부분 활용(자료 요약 등)이 적합.

💡 **왜 중요한가?** 한정된 시간에 "가장 남는 장사"를 골라야 자동화 경험이 성공으로 이어집니다.
</details>

## 4. AS-IS / TO-BE 기획서 — 개선을 '문서'로 만들기

- **AS-IS** = 현재 이렇게 하고 있다 (문제점 포함)
- **TO-BE** = 앞으로 이렇게 바꾸겠다 (개선안)

**기획서 기본 골격 (오늘의 산출물 양식)**

```
1. 대상 업무명:
2. AS-IS (현행)
   - 절차: (입력→처리→산출 단계별로)
   - 소요시간: 주/월 ___시간
   - 문제점:
3. TO-BE (개선안)
   - 개선 절차: (어느 단계에 AI/자동화를 넣는지)
   - 활용 도구: (생성형 AI / 워크플로 자동화 / 둘의 결합)
   - 기대효과: 소요시간 ___시간 → ___시간 (약 __% 절감)
4. 추진 일정 및 필요 지원
```

### 💻 [따라하기 5] AI로 기획서 초안 30초 만에 뽑기

앞의 [따라하기 4]에서 만든 업무 분해 표가 있는 **같은 대화창**에서 이어서 입력하세요.

```
위에서 분해한 업무를 바탕으로 "업무 자동화 기획서" 초안을 작성해줘.
[형식] 1.대상 업무명 / 2.AS-IS(절차·소요시간·문제점) / 3.TO-BE(개선 절차·활용 도구·기대효과) / 4.추진 일정 순서.
[조건] - 현재 소요시간은 월 6시간이라고 가정
      - TO-BE에는 생성형 AI를 활용하는 지점을 단계별로 구체적으로 명시
      - 결재 문서에 쓸 수 있는 간결한 개조식 문장으로, A4 1장 분량
```

**STEP 2.** 나온 초안에서 **사실과 다른 부분(소요시간, 절차)을 내 상황에 맞게 수정 지시**하세요.

**STEP 3.** 최종본을 저장합니다. → **이 기획서는 모듈 3-3(Zapier/Make 실습)에서 실제로 구현할 시나리오가 됩니다.**
