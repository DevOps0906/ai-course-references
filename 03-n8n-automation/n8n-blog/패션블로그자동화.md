# 📋 사전 준비 — Docker로 n8n + WordPress 환경 구축 (60~90분)

> ⚠️ **필수 사전 작업**: 교육 시작 전에 반드시 완료해주세요. 수업 중에는 환경 구축 검증만 진행합니다.

## Step 1: 시스템 요구사항 확인 (5분)

### 최소 사양

| 항목 | 최소 | 권장 |
|------|------|------|
| OS | Windows 10/11 (64비트), macOS 11+, Ubuntu 20.04+ | 동일 |
| RAM | 8GB | 16GB |
| 저장공간 | 10GB 여유 | 20GB 여유 |

### Windows 사용자 — 가상화 활성화 확인

1. `Ctrl + Shift + Esc`로 **작업 관리자** 실행
2. **성능** 탭 → **CPU** 선택
3. 우측 하단 **"가상화"**가 **"사용"**인지 확인
4. **"사용 안 함"**이면 BIOS에서 활성화 필요 (제조사별로 설정 방법 상이)

## Step 2: Docker Desktop 설치 (20~30분)

### Windows 설치 — 상세 단계

1. **Docker 다운로드 페이지 접속**
   - 브라우저 주소창에 입력: `https://www.docker.com/products/docker-desktop/`

2. **"Download for Windows"** 버튼 클릭
   - 파일명 예시: `Docker Desktop Installer.exe`
   - 크기: 약 500~600MB

3. **설치 파일 실행**
   - 다운로드 폴더에서 `Docker Desktop Installer.exe` **더블 클릭**
   - "Do you want to allow this app to make changes?" → **Yes**

4. **설치 옵션 선택 (중요!)**
   - ☑ `Use WSL 2 instead of Hyper-V` (**반드시 체크**)
   - ☑ `Add shortcut to desktop`
   - **"OK"** 클릭

5. **설치 진행 (5~10분 소요)**
   - "Unpacking files..." 진행 표시
   - 완료 후 "Installation succeeded" 메시지

6. **재부팅 필수**
   - "Close and restart" 클릭 → 컴퓨터 자동 재시작

7. **Docker Desktop 첫 실행**
   - 바탕화면 **Docker Desktop** 아이콘 더블 클릭
   - 약관 동의: "Accept"
   - Sign in 화면: **우측 상단 "Skip"** (가입 불필요)
   - 설문 화면도 건너뛰기

8. **좌측 하단 상태 확인**
   - 초록색 "Engine running" 표시가 나오면 정상
   - 빨간색이면 → Windows 재부팅 후 다시 실행

### macOS 설치 — 상세 단계

1. `https://www.docker.com/products/docker-desktop/` 접속
2. Mac 칩에 맞게 다운로드 선택
   - Intel Mac: **"Download for Mac (Intel Chip)"**
   - Apple Silicon (M1~M4): **"Download for Mac (Apple Silicon)"**
3. `Docker.dmg` 더블 클릭 → **Docker 아이콘을 Applications 폴더로 드래그**
4. **Launchpad** → **Docker** 실행
5. 시스템 권한 요청 시 암호 입력 → 허용
6. 상단 메뉴바에 🐳 고래 아이콘이 보이면 성공

### 설치 확인 — 터미널 명령

**Windows**: 시작 메뉴 → **PowerShell** 검색 → 실행
**macOS**: `Command + Space` → **Terminal** 입력 → 실행
**Linux**: Ctrl+Alt+T

아래 두 명령을 순서대로 실행:

```bash
docker --version
```

**예상 출력**:
```
Docker version 27.x.x, build xxxxxxxx
```

```bash
docker compose version
```

**예상 출력**:
```
Docker Compose version v2.x.x
```

> ⚠️ **"command not found" 에러가 나면** → Docker Desktop이 실행 중인지 다시 확인. 여전히 안 되면 컴퓨터 재부팅.

## Step 3: 프로젝트 폴더 & docker-compose.yml 작성 (15분)

### 3-1. 프로젝트 폴더 생성

**Windows (PowerShell)**:
```powershell
cd $HOME
mkdir fashion-blog
cd fashion-blog
pwd
```

**macOS / Linux (Terminal)**:
```bash
cd ~
mkdir fashion-blog
cd fashion-blog
pwd
```

> 💡 `pwd` 결과가 `.../fashion-blog`로 끝나야 합니다.

### 3-2. docker-compose.yml 파일 작성

#### Windows — 메모장으로 생성

1. **PowerShell에서 명령**:
   ```powershell
   notepad docker-compose.yml
   ```
2. "파일을 찾을 수 없음. 새로 만드시겠습니까?" → **예**
3. 메모장 창이 열리면 **아래 YAML 전체를 복사 → 붙여넣기**
4. **파일 → 다른 이름으로 저장**
   - 파일 형식: **"모든 파일 (*.*)"**
   - 파일 이름: `docker-compose.yml`
   - 인코딩: **UTF-8** 선택
   - 저장

#### macOS / Linux — nano 에디터

```bash
nano docker-compose.yml
```

#### 복사할 YAML 내용 (전체)

```yaml
services:
  # ═══════════════════════════════════════
  # WordPress용 데이터베이스 (MariaDB)
  # ═══════════════════════════════════════
  wordpress_db:
    image: mariadb:11
    container_name: fashion_db
    restart: unless-stopped
    environment:
      MARIADB_ROOT_PASSWORD: rootpass1234
      MARIADB_DATABASE: wordpress
      MARIADB_USER: wpuser
      MARIADB_PASSWORD: wppass1234
    volumes:
      - wp_db_data:/var/lib/mysql
    networks:
      - blog_net

  # ═══════════════════════════════════════
  # WordPress 패션 블로그
  # ═══════════════════════════════════════
  wordpress:
    image: wordpress:latest
    container_name: fashion_wordpress
    restart: unless-stopped
    depends_on:
      - wordpress_db
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: wordpress_db:3306
      WORDPRESS_DB_NAME: wordpress
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: wppass1234
      WORDPRESS_DEBUG: "0"
    volumes:
      - wp_data:/var/www/html
    networks:
      - blog_net

  # ═══════════════════════════════════════
  # n8n 워크플로우 자동화
  # ═══════════════════════════════════════
  n8n:
    image: n8nio/n8n:latest
    container_name: fashion_n8n
    restart: unless-stopped
    ports:
      - "5678:5678"
    environment:
      - N8N_HOST=localhost
      - N8N_PORT=5678
      - N8N_PROTOCOL=http
      - NODE_ENV=production
      - WEBHOOK_URL=http://localhost:5678/
      - GENERIC_TIMEZONE=Asia/Seoul
      - TZ=Asia/Seoul
      - N8N_SECURE_COOKIE=false
      - N8N_RUNNERS_ENABLED=true
    volumes:
      - n8n_data:/home/node/.n8n
    networks:
      - blog_net

volumes:
  wp_db_data:
  wp_data:
  n8n_data:

networks:
  blog_net:
    driver: bridge
```

> ⚠️ **주의사항**:
> - YAML은 **들여쓰기가 매우 중요**합니다. 공백 2칸으로 맞춰야 합니다.
> - 탭(Tab)을 쓰면 안 됩니다. 반드시 **스페이스**만 사용.
> - 복사할 때 앞뒤 빈 줄은 없어도 됩니다.

### 3-3. 파일 저장 확인

**PowerShell / Terminal**:
```bash
ls docker-compose.yml
```

파일이 보이면 성공.

## Step 4: Docker 실행 & 초기 설정 (15분)

### 4-1. 컨테이너 3개 한 번에 실행

프로젝트 폴더(`fashion-blog`) 안에서:

```bash
docker compose up -d
```

**예상 출력**:
```
[+] Running 4/4
 ✔ Network fashion-blog_blog_net       Created
 ✔ Container fashion_db                Started
 ✔ Container fashion_wordpress         Started
 ✔ Container fashion_n8n               Started
```

> 💡 **첫 실행 시 5~10분 소요**: 이미지 다운로드 시간입니다. "Pulling fs layer..." 메시지가 나오면 정상.

### 4-2. 실행 상태 확인

```bash
docker compose ps
```

**예상 출력**:
```
NAME                IMAGE                    STATUS          PORTS
fashion_db          mariadb:11               Up              3306/tcp
fashion_n8n         n8nio/n8n:latest         Up              0.0.0.0:5678->5678/tcp
fashion_wordpress   wordpress:latest         Up              0.0.0.0:8080->80/tcp
```

3개 모두 **"Up"** 상태여야 합니다.

> ❌ **"Exit (1)" 상태라면**: `docker compose logs [컨테이너명]`으로 원인 확인. 대부분 포트 충돌 또는 RAM 부족.

### 4-3. n8n 초기 설정 — 브라우저 접속

1. 브라우저 주소창: `http://localhost:5678`
2. "Set up owner account" 화면 표시

**입력 정보**:

| 필드 | 입력 예시 |
|------|----------|
| Email | `fashion@mylocal.com` |
| First Name | `패션` |
| Last Name | `블로거` |
| Password | (8자 이상, 숫자 포함 — 예: `fashion1234`) |

3. 뉴스레터 동의 화면 → **"Not now"** 또는 건너뛰기
4. "What do you plan to do?" → **"Skip"**
5. n8n 메인 화면 (Workflows 페이지)이 보이면 성공

### 4-4. WordPress 초기 설정 — 브라우저 접속

1. 브라우저 주소창: `http://localhost:8080`
2. **언어 선택**: "한국어" → 계속

3. **사이트 정보 입력**:

   | 필드 | 입력 |
   |------|------|
   | 사이트 제목 | `룩북 다이어리` |
   | 사용자명 | `fashionadmin` |
   | 비밀번호 | (복잡한 비밀번호 — 생성된 것 그대로 사용 추천) |
   | 비밀번호 확인 | (표시된 비밀번호 어딘가에 메모!) |
   | 이메일 | `fashion@mylocal.com` |
   | 검색 엔진 방지 | ☑ **반드시 체크** (로컬 테스트이므로) |

4. **"WordPress 설치"** 클릭
5. "성공!" 화면 → **"로그인"** 클릭
6. 방금 입력한 사용자명/비밀번호로 로그인

> 📝 **비밀번호 메모 필수**: WordPress 초기 비밀번호는 한 번만 표시됩니다. Notepad나 메모 앱에 저장해 두세요.

## Step 5: 패션 블로그 카테고리 구조 만들기 (10분)

WordPress 관리자 로그인 상태에서:

1. 좌측 메뉴 **"글"** → **"카테고리"** 클릭

2. **"새 카테고리 추가"** 섹션에서 5개 카테고리 차례로 생성:

| 이름 | 슬러그 | 설명 |
|---------|-------|------|
| 트렌드 | `trends` | 시즌별 트렌드, 패션위크, 런웨이 |
| 스타일링 | `styling` | 코디 가이드, 체형별 팁 |
| 리뷰 | `reviews` | 제품·브랜드 리뷰 |
| 쇼핑가이드 | `shopping` | 가격대별 추천 |
| 룩북 | `lookbook` | AI 생성 스타일링 이미지 |

각 카테고리는:
- 이름 입력 → 슬러그 입력 (영문 소문자) → 설명 입력 → **"새 카테고리 추가"** 버튼 클릭

3. 우측 카테고리 목록에 **총 6개** (기본 "미분류" + 5개 추가) 표시되면 완료

### 📌 카테고리 ID 메모 (나중에 필요)

우측 목록에서 각 카테고리 **"편집"** 위에 마우스 올리기 → 브라우저 하단에 URL 표시:

```
http://localhost:8080/wp-admin/term.php?taxonomy=category&tag_ID=5&...
                                                        ^^^^
                                                        이 숫자가 ID!
```

**메모 양식**:
```
트렌드     = 2
스타일링   = 3
리뷰       = 4
쇼핑가이드 = 5
룩북       = 6
```

> ⚠️ 환경마다 ID가 다를 수 있으니 **본인 환경의 ID를 메모**하세요.

## Step 6: 정상 동작 확인 (5분)

아래 6가지를 모두 체크하면 사전 준비 완료입니다.

- [ ] `docker compose ps` → 3개 컨테이너 모두 **Up**
- [ ] `http://localhost:5678` → n8n 로그인 성공 (Workflows 페이지 보임)
- [ ] `http://localhost:8080` → WordPress 사이트 표시
- [ ] `http://localhost:8080/wp-admin` → 관리자 대시보드 로그인 성공
- [ ] 카테고리 5개 (트렌드/스타일링/리뷰/쇼핑가이드/룩북) 생성 완료
- [ ] 카테고리 ID 5개 메모 완료

✅ 모두 체크되면 **사전 준비 완료!** 1교시로 넘어갑니다.

### 🆘 자주 발생하는 문제 Top 3

**문제 1. `http://localhost:8080`이 안 열림**
→ 원인: Docker가 안 떠 있거나, 포트 8080을 다른 프로그램이 사용 중
→ 해결: `docker compose ps`로 `fashion_wordpress`가 Up인지 확인 / 8080 대신 `"8090:80"`으로 변경 후 `docker compose up -d`

**문제 2. n8n 화면이 하얗게만 나옴**
→ 원인: 브라우저 캐시 또는 쿠키 문제

## 1-1. 자체 호스팅 n8n 핵심 이해 (10분)

### ⚠️ Docker 내부 통신 — 가장 중요한 개념

Docker 환경에서는 "주소"가 두 종류입니다. 반드시 구분해야 합니다.

```
❌ http://localhost:8080   → n8n 안에서 localhost = n8n 자기 자신
✅ http://wordpress        → Docker 네트워크 안에서 서비스 이름으로 접근
```

| 상황 | URL |
|------|-----|
| 내가 브라우저에서 WordPress 접속 | `http://localhost:8080` |
| n8n 워크플로우에서 WordPress API 호출 | `http://wordpress` ⭐ |
| 내가 브라우저에서 n8n 접속 | `http://localhost:5678` |

> 💡 **비유로 이해하기**:
> - 브라우저는 집 밖에서 초인종을 누르는 사람 → 집 주소(`localhost:8080`) 필요
> - n8n은 같은 아파트 옆집 주민 → 호수 이름(`wordpress`)만 알면 됨
> - 둘은 같은 아파트(Docker 네트워크) 안에 삽니다.

### n8n 2.x 핵심 변경사항

- **Save vs Publish**:
  - `Save` = 초안 저장 (Manual Trigger는 동작 OK)
  - `Publish` = 실제 배포 (Webhook, Schedule Trigger 활성화)
- **Code 노드**: Task Runner에서 격리 실행 (`process.env` 사용 불가)
- **날짜 함수**: `.toFormat()` 사용 (`.format()` 아님)
- **Expression 표기**: `{{ }}` 안에 JavaScript

#### 5-3. JavaScript 코드 입력

Code 영역에 아래 코드 **전체를 복사 → 붙여넣기**:

```javascript
// ── AI 응답 파싱 ──
const rawContent = $input.first().json.output[0].content[0].text;
let jsonStr = rawContent.replace(/```json\n?/g, '').replace(/```\n?/g, '').trim();

let ideas = [];
try {
  ideas = JSON.parse(jsonStr);
} catch (e) {
  return [{ json: { 상태: '파싱 실패', 원본: rawContent, 에러: e.message } }];
}

// ── 현재 시즌 자동 판별 ──
const now = new Date();
const month = now.getMonth() + 1;

let season, seasonEn, mood, colors;
if (month >= 3 && month <= 5) {
  season = '봄'; seasonEn = 'spring';
  mood = 'fresh, pastel, light';
  colors = '파스텔 핑크, 라벤더, 민트, 아이보리';
} else if (month >= 6 && month <= 8) {
  season = '여름'; seasonEn = 'summer';
  mood = 'bright, vibrant, minimal';
  colors = '화이트, 스카이블루, 코럴, 옐로우';
} else if (month >= 9 && month <= 11) {
  season = '가을'; seasonEn = 'autumn';
  mood = 'warm, earthy, textured';
  colors = '버건디, 카멜, 올리브, 테라코타';
} else {
  season = '겨울'; seasonEn = 'winter';
  mood = 'cozy, rich, layered';
  colors = '네이비, 차콜, 보르도, 크림';
}

// ── 시즌별 추천 키워드 ──
const seasonKeywords = {
  '봄': ['봄코디', '트렌치코트', '가디건', '로퍼', '파스텔'],
  '여름': ['여름코디', '린넨', '원피스', '샌들', '시어서커'],
  '가을': ['가을코디', '니트', '자켓', '로퍼', '트위드'],
  '겨울': ['겨울코디', '패딩', '코트', '부츠', '머플러']
};

// ── 아이디어에 메타 정보 추가 ──
const enrichedIdeas = ideas.map((idea, index) => ({
  번호: index + 1,
  ...idea,
  시즌: season,
  시즌무드: mood,
  시즌컬러: colors,
  추천키워드: seasonKeywords[season],
  생성일시: now.toISOString().slice(0, 19).replace('T', ' '),
  상태: '대기중'
}));

// ── 인기도순 정렬 ──
enrichedIdeas.sort((a, b) => (b.예상인기도 || 0) - (a.예상인기도 || 0));

return enrichedIdeas.map(idea => ({ json: idea }));
```

#### 5-4. 코드 설명 (이해하고 가기)

- **라인 1~2**: AI 응답에 종종 포함되는 ``` ```json ``` ``` 코드 펜스 제거
- **라인 4~10**: JSON 파싱 실패 시 원본 반환 (디버깅용)
- **라인 13~32**: 현재 월을 읽어 4계절 중 하나로 자동 판별
- **라인 35~40**: 각 시즌별 트렌드 키워드 매핑
- **라인 43~52**: 원본 아이디어에 시즌 정보 추가
- **라인 55**: 인기도 높은 순으로 정렬
- **라인 57**: 각 아이디어를 n8n 아이템으로 변환하여 반환

#### 5-3. 코드 입력 (전체 복사)

```javascript
const content = $input.first().json.output[0].content[0].text;
const keyword = $('Edit Fields').first().json.키워드;
const category = $('Edit Fields').first().json.카테고리;

// ═══ 기본 SEO 체크 ═══
const charCount = content.length;
const h1Count = (content.match(/^#\s/gm) || []).length;
const h2Count = (content.match(/^##\s/gm) || []).length;

const keywordMatches = (content.match(new RegExp(keyword, 'gi')) || []).length;
const density = ((keywordMatches * keyword.length) / charCount * 100).toFixed(2);

// ═══ 패션 블로그 특화 체크 ═══

// 1. 가격대 언급
const priceTerms = ['하이엔드', '미드', 'SPA', '합리적', '명품', '만원', '가격', '프리미엄'];
const hasPriceInfo = priceTerms.some(t => content.includes(t));
const priceCount = priceTerms.reduce((s, t) => s + (content.match(new RegExp(t, 'g')) || []).length, 0);

// 2. 스타일링 팁
const stylingTerms = ['스타일링', '코디', '매칭', '포인트', '팁', '추천', '연출', '활용'];
const stylingCount = stylingTerms.reduce((s, t) => s + (content.match(new RegExp(t, 'g')) || []).length, 0);

// 3. 체형/상황별 팁
const contextTerms = ['체형', '키', '상황', '오피스', '데일리', '데이트', '캐주얼', '통통', '슬림', '볼륨'];
const hasContextualTips = contextTerms.some(t => content.includes(t));

// 4. 이모지 수
const emojiCount = (content.match(/[\u{1F300}-\u{1F9FF}]|[\u{2600}-\u{26FF}]/gu) || []).length;

// 5. CTA
const ctaTerms = ['댓글', '저장', '공유', '팔로우', '알려주세요', '어떠세요', '좋아요'];
const hasCTA = ctaTerms.some(t => content.includes(t));

// 6. 체크리스트 존재
const hasChecklist = content.includes('✅') || content.includes('체크리스트') || content.includes('핵심 정리');

// ═══ 점수 계산 ═══
let score = 100;
const issues = [];
const wins = [];

// 기본 체크
if (charCount < 1500) { score -= 20; issues.push(`글자수 부족 (${charCount}자)`); }
else { wins.push(`✅ 충분한 분량 (${charCount}자)`); }

if (h2Count < 4) { score -= 15; issues.push(`섹션 부족 (H2 ${h2Count}개)`); }
else { wins.push(`✅ 체계적 구조 (${h2Count}개 섹션)`); }

if (density < 0.5) { score -= 10; issues.push(`키워드 밀도 낮음 (${density}%)`); }
if (density > 3) { score -= 10; issues.push(`키워드 남용 (${density}%)`); }

// 패션 특화 체크
if (!hasPriceInfo) { score -= 10; issues.push(`가격대 정보 없음`); }
else { wins.push(`✅ 가격대 정보 포함 (${priceCount}회)`); }

if (stylingCount < 5) { score -= 10; issues.push(`스타일링 팁 부족 (${stylingCount}회)`); }
else { wins.push(`✅ 풍부한 스타일링 팁 (${stylingCount}회)`); }

if (!hasContextualTips) { score -= 5; issues.push(`체형/상황별 팁 없음`); }
else { wins.push(`✅ 맞춤형 팁 포함`); }

if (emojiCount === 0) { score -= 5; issues.push(`이모지 없음 (패션 블로그 권장)`); }
else if (emojiCount > 20) { score -= 5; issues.push(`이모지 남용 (${emojiCount}개)`); }
else { wins.push(`✅ 적절한 이모지 (${emojiCount}개)`); }

if (!hasCTA) { score -= 5; issues.push(`독자 참여 CTA 없음`); }
else { wins.push(`✅ CTA 포함`); }

if (!hasChecklist) { score -= 5; issues.push(`핵심 정리 체크리스트 없음`); }
else { wins.push(`✅ 핵심 정리 포함`); }

// ═══ 등급 판정 ═══
let grade;
if (score >= 90) grade = 'S (발행 추천)';
else if (score >= 80) grade = 'A (소폭 수정 후 발행)';
else if (score >= 70) grade = 'B (수정 필요)';
else grade = 'C (재작성 필요)';

// ═══ H1 제목 추출 ═══
const titleMatch = content.match(/^#\s+(.+)$/m);
const title = titleMatch ? titleMatch[1] : '제목없음';

// ═══ Markdown → HTML 변환 ═══
let html = content
  .replace(/^#\s+(.+)$/gm, '<h1>$1</h1>')
  .replace(/^##\s+(.+)$/gm, '<h2>$1</h2>')
  .replace(/^###\s+(.+)$/gm, '<h3>$1</h3>')
  .replace(/\*\*(.+?)\*\*/g, '<strong>$1</strong>')
  .replace(/\*(.+?)\*/g, '<em>$1</em>')
  .replace(/\[(.+?)\]\((.+?)\)/g, '<a href="$2">$1</a>')
  .replace(/^\-\s+(.+)$/gm, '<li>$1</li>')
  .split('\n\n')
  .map(p => {
    if (p.trim().startsWith('<')) return p;
    if (p.trim() === '') return '';
    return `<p>${p.trim()}</p>`;
  })
  .join('\n');

html = html.replace(/(<li>.*?<\/li>\n?)+/gs, m => `<ul>\n${m}</ul>\n`);

return [{
  json: {
    제목: title,
    카테고리: category,
    본문_MD: content,
    본문_HTML: html,
    글자수: charCount,
    H2개수: h2Count,
    키워드밀도: `${density}%`,
    가격정보: hasPriceInfo ? '✅' : '❌',
    스타일링팁수: stylingCount,
    체형상황별팁: hasContextualTips ? '✅' : '❌',
    이모지수: emojiCount,
    CTA여부: hasCTA ? '✅' : '❌',
    체크리스트: hasChecklist ? '✅' : '❌',
    품질점수: score,
    등급: grade,
    통과여부: score >= 70 ? '✅ 통과' : '❌ 재작성 필요',
    강점: wins,
    이슈: issues,
    작성일시: new Date().toISOString().slice(0, 19).replace('T', ' ')
  }
}];
```

#### 5-4. 코드 이해 포인트

## 3-2. WordPress Application Password 생성 (15분)

### 🎯 왜 Application Password가 필요한가?

일반 비밀번호로 API를 쓰면 보안이 약합니다. WordPress는 API 전용 비밀번호(`Application Password`)를 별도 발급할 수 있으며, 유출돼도 필요시 개별 폐기 가능합니다.

## 3-4. 실습 3-3: 생성한 이미지를 WordPress에 실제로 반영하기 (30분) ⭐ 핵심 보강

### 🎯 목표

지금까지는 Gemini로 이미지를 **생성만** 했고, WordPress에는 이미지가 들어가지 않은 상태입니다. 이 섹션에서는 생성된 이미지를:

1. **WordPress 미디어 라이브러리에 업로드**
2. **글의 대표 이미지(Featured Image)로 설정**
3. **본문 최상단에도 이미지 삽입**

이 세 가지를 모두 자동화합니다.

### 📌 왜 별도 작업이 필요한가?

n8n의 **기본 WordPress 노드는 Post·Page·User만 지원**하고 Media(이미지/파일) 업로드는 지원하지 않습니다. 따라서 WordPress REST API의 Media 엔드포인트를 **HTTP Request 노드**로 직접 호출해야 합니다.

```
POST http://wordpress/wp-json/wp/v2/media
  Authorization: Basic <Base64(user:app_password)>
  Content-Type: image/png
  Content-Disposition: attachment; filename="fashion.png"
  Body: [이미지 바이너리]
```

응답으로 `id`(미디어 ID)와 `source_url`(이미지 URL)이 오고, 이것을 WordPress 노드의 **Featured Media** 필드와 본문 HTML의 `<img>` 태그로 연결합니다.

### 완성된 3교시 최종 워크플로우 구조

```
Manual Trigger
    → Edit Fields
    → OpenAI #1 (SEO 메타)
    → OpenAI #2 (본문 작성)
    → Code (품질 체크 + HTML + 카테고리ID)  ← 2교시 산출물
    → Code_이미지프롬프트 (카테고리별 프롬프트)
    → Google Gemini (이미지 생성, Binary 출력)
    → HTTP Request (WordPress Media 업로드) ⭐ 신규
    → Code_미디어병합 (Media ID + 본문에 img 삽입) ⭐ 신규
    → WordPress (Post Create + Featured Media) ⭐ 수정
    → Code_최종보고
```

### Step 1: HTTP Request 노드 추가 — 이미지 업로드 (10분)

`실습3_이미지포함_패션` 워크플로우에 돌아와서:

#### 1-1. 노드 추가

1. **Google Gemini**(이미지 생성) 노드 우측 **[+]** 클릭
2. 검색창: `http`
3. **"HTTP Request"** 선택
4. 생성된 노드 이름 변경: 더블클릭 → `HTTP_이미지업로드`

#### 1-2. 기본 설정

| 필드 | 값 |
|------|-----|
| **Method** | `POST` |
| **URL** | `http://wordpress/wp-json/wp/v2/media` |

> ⚠️ URL은 반드시 `http://wordpress` (서비스 이름)를 사용합니다. `http://localhost:8080` 아님!

#### 1-3. Authentication 설정

1. **Authentication** 드롭다운 → `Generic Credential Type` 선택
2. 바로 아래 **Generic Auth Type** → `Basic Auth` 선택
3. **Basic Auth** 필드 옆 **"Create New Credential"** 클릭
4. 팝업 창에서 입력:

| 필드 | 값 |
|------|-----|
| **User** | `fashionadmin` |
| **Password** | (WordPress Application Password — 3-2에서 만든 것) |

5. 이름: `My WordPress Basic Auth` → Save

> 💡 이미 `My WordPress` Credential이 있지만, 그건 n8n WordPress 노드 전용이라 HTTP Request에서는 재사용할 수 없습니다. Basic Auth용을 별도로 만들어야 합니다.

#### 1-4. Send Headers 설정

1. **Send Headers** 토글 → **On**
2. **"Add Parameter"** 2번 클릭

| # | Name | Value |
|---|------|-------|
| 1 | `Content-Type` | `image/png` |
| 2 | `Content-Disposition` | `attachment; filename="fashion-{{ $('Code').first().json.카테고리 }}-{{ $now.toFormat('yyyyMMddHHmm') }}.png"` |

> ⚠️ **Content-Disposition** 값은 반드시 **Expression 모드(fx 버튼)**로 입력해야 `{{ }}` 치환이 작동합니다.

> 💡 **Gemini는 PNG로 이미지를 반환합니다.** 만약 JPEG인 경우에는 `image/jpeg`와 `.jpg`로 수정하세요. 모델이나 설정에 따라 다를 수 있으니, Gemini 노드 Output의 Binary 탭에서 `mimeType`을 확인하세요.

#### 1-5. Send Body 설정 (핵심!)

1. **Send Body** 토글 → **On**
2. **Body Content Type** 드롭다운 → **`n8n Binary File`** 선택

   > ⚠️ `Form URLencoded`나 `JSON` 아님! 반드시 `n8n Binary File`을 선택해야 이미지 바이너리가 전송됩니다.

3. **Input Data Field Name** → `data`

   > 💡 `data`는 Gemini 노드가 이미지를 담아 보내는 필드명입니다. Gemini Output의 Binary 탭에서 필드명을 확인할 수 있습니다.

#### 1-6. Options 추가 (선택)

**Options → Add Option → Response → Response Format** → `JSON` 선택

(기본값이 자동 감지지만 명시적으로 지정하면 안전)

#### 1-7. 테스트

1. **Execute step** 클릭
2. 성공하면 Output에 다음과 같은 JSON이 표시됩니다:

```json
{
  "id": 87,
  "date": "2026-04-25T14:30:00",
  "slug": "fashion-styling-202604251430",
  "type": "attachment",
  "link": "http://localhost:8080/?attachment_id=87",
  "title": {
    "rendered": "fashion-styling-202604251430"
  },
  "media_type": "image",
  "mime_type": "image/png",
  "source_url": "http://localhost:8080/wp-content/uploads/2026/04/fashion-styling-202604251430.png",
  ...
}
```

**핵심 필드 2개**:
- `id` → WordPress 글의 **Featured Media**로 연결할 번호
- `source_url` → 본문 HTML에 **`<img src="...">`**로 삽입할 URL

> 🆘 **401 Unauthorized 에러** → Basic Auth Credential의 Password가 일반 로그인 비밀번호일 가능성. **Application Password**로 재확인.
>
> 🆘 **"Sorry, you are not allowed to create posts as this user" 에러** → `fashionadmin` 계정이 실제로 존재하고 관리자 권한인지 확인.
>
> 🆘 **"rest_upload_sideload_error"** → Content-Type과 실제 바이너리 형식 불일치. `image/png`이 맞는지 확인.

#### 1-8. WordPress에서 업로드 확인

1. 브라우저: `http://localhost:8080/wp-admin/upload.php`
2. 방금 업로드된 이미지가 목록 최상단에 있어야 함
3. 클릭 → 파일명, URL, 미리보기 확인

> ✅ 여기까지 성공하면 **이미지가 WordPress 미디어 라이브러리에 들어간 상태**입니다.

### Step 2: Code 노드 — 미디어 정보 병합 & 본문에 이미지 삽입 (8분)

#### 2-1. 노드 추가

1. HTTP_이미지업로드 노드 옆 **[+]** → `code` 검색 → **Code**
2. 이름: `Code_미디어병합`

#### 2-2. 설정

- **Language**: `JavaScript`
- **Mode**: `Run Once for All Items`

#### 2-3. JavaScript 코드

```javascript
// ─ 이전 노드들의 데이터 가져오기 ─
const post = $('Code').first().json;        // 품질 체크 결과 (제목, 본문_HTML, 카테고리ID 등)
const media = $json;                         // HTTP Request의 WordPress 응답 (id, source_url)

// ─ 안전 체크 ─
if (!media.id || !media.source_url) {
  return [{
    json: {
      에러: '이미지 업로드 실패',
      미디어응답: media
    }
  }];
}

// ─ 본문 HTML 맨 앞에 이미지 삽입 ─
// <figure>로 감싸면 WordPress 기본 스타일이 적용됩니다
const imageBlock = `
<figure class="wp-block-image aligncenter size-large">
  <img src="${media.source_url}" 
       alt="${post.제목}"
       title="${post.제목}"
       class="fashion-hero-image"
       style="width:100%; max-width:900px; height:auto; margin:0 auto; display:block;" />
  <figcaption style="text-align:center; color:#888; font-size:0.9em; margin-top:8px;">
    AI 생성 이미지 · ${post.카테고리}
  </figcaption>
</figure>
<br/>
`;

// H1 제목 뒤에 이미지 삽입 (H1이 없으면 맨 앞)
let contentWithImage;
if (post.본문_HTML.includes('</h1>')) {
  // H1 닫는 태그 바로 뒤에 이미지 삽입
  contentWithImage = post.본문_HTML.replace('</h1>', '</h1>\n' + imageBlock);
} else {
  // H1이 없으면 맨 앞에 삽입
  contentWithImage = imageBlock + post.본문_HTML;
}

// ─ 다음 노드(WordPress)로 전달 ─
return [{
  json: {
    // 기존 필드들 그대로 전달
    ...post,
    // 이미지 반영된 본문으로 덮어쓰기
    본문_HTML_이미지포함: contentWithImage,
    // WordPress Featured Media에 쓸 미디어 ID
    미디어ID: media.id,
    미디어URL: media.source_url,
    미디어파일명: media.slug,
    // 확인용 로그
    이미지삽입위치: post.본문_HTML.includes('</h1>') ? 'H1 뒤' : '본문 최상단',
    업로드시각: new Date().toISOString().slice(0, 19).replace('T', ' ')
  }
}];
```

#### 2-4. 코드 설명

- **라인 3~4**: 두 개의 이전 노드에서 각각 데이터 가져오기
  - `$('Code').first().json` → 2교시에서 만든 품질 체크 결과 (제목, 본문_HTML 등)
  - `$json` → 바로 직전 HTTP_이미지업로드의 응답 (id, source_url)
- **라인 7~14**: 업로드 실패 시 에러 반환하여 WordPress 노드로 안 가도록 방어
- **라인 17~27**: `<figure>` 태그로 이미지 래핑 (WordPress 기본 스타일과 호환)
- **라인 30~37**: H1 제목 뒤에 이미지를 삽입 (제목 먼저, 그 다음 히어로 이미지)
- **라인 40~51**: 다음 노드로 넘길 데이터 구성

#### 2-5. 테스트

**Execute step** 클릭 → Output 확인:

```json
{
  "제목": "2026 봄, 트렌치코트 하나로 7가지 코디 완성하기",
  "카테고리": "스타일링",
  "카테고리ID": 4,
  "본문_HTML_이미지포함": "<h1>2026 봄, 트렌치코트...</h1>\n<figure class=\"wp-block-image...\"><img src=\"http://localhost:8080/wp-content/uploads/...png\" ...",
  "미디어ID": 87,
  "미디어URL": "http://localhost:8080/wp-content/uploads/2026/04/fashion-styling-202604251430.png",

### Step 3: WordPress 노드 수정 — Featured Media 연결 (7분)

기존에 만들어 둔 **WordPress_초안저장** 노드를 수정합니다.

#### 3-1. 입력 참조 경로 변경

기존 WordPress 노드는 `$('Code').first().json`을 참조했지만, 이제는 `Code_미디어병합`을 참조해야 합니다.

**Title** (Expression 모드):

변경 전:
```
{{ $('Code in JavaScript1').item.json['제목'] }}
```

변경 후:
```
{{ $('Code_미디어병합').item.json['제목'] }}
```

**Content** (Expression 모드):

변경 전:
```
{{ $('Code in JavaScript1').item.json['본문_HTML'] }}
```

변경 후 (⭐ 이미지 포함된 HTML로):
```
{{ $('Code_미디어병합').item.json['본문_HTML_이미지포함'] }}
```

**Categories** (Expression 모드):
```
{{ $('Code_미디어병합').item.json['카테고리ID'] }}

**"Additional Fields"** → **"Add Field"** → **"Featured Media ID"** 선택

값 (Expression 모드):

### 🎨 심화: 여러 위치에 이미지 삽입하기 (선택, 5분)

한 글에 이미지 여러 장을 넣고 싶다면:

**방법 1. Gemini를 여러 번 호출**

```
Gemini #1 (히어로 이미지) → HTTP Request → 
Gemini #2 (본문 중간 이미지) → HTTP Request → 
Code (여러 이미지 URL을 본문의 H2 섹션마다 삽입) → WordPress
```

**방법 2. Code 노드에서 섹션별 이미지 자동 삽입**

```javascript
// Code_미디어병합을 확장
// H2 태그 앞마다 다른 이미지(또는 같은 이미지)를 삽입
const h2Regex = /<h2>([^<]+)<\/h2>/g;
let imageCounter = 0;
const contentWithImages = post.본문_HTML.replace(h2Regex, (match, title) => {
  imageCounter++;
  // 모든 H2 앞에 같은 이미지를 넣거나, 배열의 N번째 이미지 사용
  return `${imageBlock}\n${match}`;
});
```

**방법 3. WordPress 블록 에디터용 `<!-- wp:image -->` 주석 사용**

```html
<!-- wp:image {"id":87,"sizeSlug":"large"} -->
<figure class="wp-block-image size-large">
  <img src="..." alt="..." class="wp-image-87"/>
</figure>
<!-- /wp:image -->
```

이렇게 쓰면 WordPress 블록 에디터에서 "이미지 블록"으로 인식되어 편집이 쉬워집니다.

### 🆘 자주 발생하는 문제

**문제 1. "Application Password" 섹션이 보이지 않음**
→ wp-config.php에 필터를 추가했는지 확인 / wordpress 컨테이너를 재시작했는지 확인

**문제 2. WordPress Credential Connection 실패 (401 Unauthorized)**
→ URL이 `http://wordpress`인가 (`http://localhost:8080` 아님) / Application Password를 복사했는가 (일반 비밀번호 아님)

**문제 3. 카테고리가 "미분류"로 저장됨**
→ Code 노드에서 `categoryMap`의 ID가 실제 WordPress 카테고리 ID와 일치하는가 확인 (사전 준비 Step 5에서 메모한 ID 사용)

**문제 4. 본문이 HTML 태그가 그대로 보임**
→ Content가 `{{ $json.본문_MD }}`가 아니라 `{{ $json.본문_HTML }}`인지 확인

**문제 5. HTTP Request 이미지 업로드 시 "400 Bad Request"** ⭐
→ Body Content Type이 **`n8n Binary File`**인지 확인 (JSON/Form이면 안 됨) / Input Data Field Name이 `data`인지 확인 (Gemini 노드의 Binary 필드명)

**문제 6. "rest_upload_sideload_error" 에러** ⭐
→ Content-Type 헤더(`image/png`)와 실제 파일 포맷이 불일치. Gemini Output Binary 탭에서 `mimeType` 확인 후 일치시킴

**문제 7. 이미지는 업로드됐는데 글에 반영 안 됨** ⭐
→ WordPress 노드의 Content가 `본문_HTML`을 참조하는지(구버전) `본문_HTML_이미지포함`을 참조하는지(보강 버전) 확인 / Featured Media ID 필드를 추가했는지 확인

**문제 8. 대표 이미지가 글 목록 썸네일로 안 보임** ⭐
→ 사용 중인 WordPress 테마가 썸네일 지원하는지 확인 (기본 테마는 지원). `featured_media`는 숫자 ID(정수)여야 하며 따옴표 들어가면 안 됨

**문제 9. 본문의 이미지가 깨져 보임 (X 아이콘)** ⭐
→ `source_url`이 `http://localhost:8080/...`으로 시작하는지 확인. n8n 내부에서는 `http://wordpress`를 쓰지만 업로드 응답의 source_url은 WordPress가 외부 접근 URL로 반환하므로 올바름. 브라우저 캐시 문제이면 Ctrl+Shift+R로 강제 새로고침

## 4-2. Schedule Trigger & 요일별 로테이션 (10분)

### 🎯 목표

Manual Trigger를 Schedule Trigger로 바꿔서 **매일 자동 실행**하는 시스템을 만듭니다.

### Step 1: Schedule Trigger로 교체 (3분)

1. 워크플로우 상단 **⋮ 메뉴** → Duplicate → 이름: `실습4_스케줄_버전`
2. Manual Trigger 노드 삭제
3. 빈 자리에 **Schedule Trigger** 추가
   - **[+]** → `schedule` 검색 → **Schedule Trigger**
4. 설정:
   - **Trigger Interval**: `Days`
   - **Hour**: `9`
   - **Minute**: `0`
5. Schedule Trigger 옆 → 기존 Edit Fields 연결

### Step 2: Edit Fields 대신 Code — 요일별 카테고리 로테이션 (5분)

Edit Fields 삭제 → Code 노드로 교체:

```javascript
const dayMap = {
  1: '트렌드',      // 월
  2: '스타일링',    // 화
  3: '리뷰',        // 수
  4: '쇼핑가이드',  // 목
  5: '룩북'         // 금
};

const today = new Date().getDay();
const category = dayMap[today];

if (!category) {
  // 주말 → 빈 배열 반환 → 워크플로우 중단
  return [];
}

return [{
  json: {
    카테고리: category,
    요일: ['일', '월', '화', '수', '목', '금', '토'][today],
    날짜: new Date().toISOString().slice(0, 10)
  }
}];
```

> 💡 주말에 `return []`을 반환하면 워크플로우가 자연스럽게 중단됩니다.

### Step 3: Publish 필수! (2분)

Schedule Trigger를 실제로 동작시키려면:

- 워크플로우 우측 상단 **"Inactive" 토글을 "Active"로 변경** (또는 "Publish")
- Docker 컨테이너가 24시간 실행 중이어야 스케줄 동작

> ⚠️ **중요**: 로컬 PC가 꺼져있으면 Schedule도 중단됩니다. 24시간 자동 운영이 필요하면 **VPS(클라우드 서버)**로 마이그레이션해야 합니다.

## 💬 자주 묻는 질문

**Q1. AI 패션 글이 구글에 페널티 받지 않나요?**
→ 순수 AI 글은 위험합니다. **본인 경험·실착 사진·구매 후기**를 반드시 추가하세요. Draft로 저장 후 검토·보강 후 발행하는 워크플로우를 꼭 지키세요.

**Q2. 시즌이 바뀔 때 설정을 바꿔야 하나요?**
→ 아닙니다! Code 노드가 **자동으로 현재 월을 읽어 시즌 판별**합니다. 4월에 실행하면 "봄", 7월에 실행하면 "여름"으로 자동 전환됩니다.

**Q3. 이미지 저작권은?**
→ Gemini로 생성한 이미지는 상업 사용 가능합니다. 단, 실제 브랜드 제품 사진은 별도 허가 필요.

**Q3-1. 왜 WordPress 노드가 아니라 HTTP Request로 이미지를 업로드하나요?** ⭐
→ n8n의 기본 WordPress 노드는 **Post·Page·User만 지원**하고 Media 엔드포인트는 지원하지 않습니다. 따라서 `/wp-json/wp/v2/media` 엔드포인트를 HTTP Request로 직접 호출해야 합니다. 대신 Post 생성은 여전히 WordPress 노드를 쓰고, `featured_media` 필드로 업로드된 이미지 ID만 넘깁니다.

**Q3-2. 이미지를 본문 여러 곳에 넣을 수 있나요?** ⭐
→ 가능합니다. 방법은 3가지:
> (1) Gemini를 여러 번 호출 → HTTP Request 여러 개 → Code에서 각 이미지 URL을 H2 섹션마다 삽입
> (2) 같은 이미지를 반복 삽입 (H2마다 같은 히어로 이미지)
> (3) WordPress 블록 에디터용 `<!-- wp:image -->` 주석 포함 HTML 사용
> 3-4 실습의 "심화" 섹션 참고.

**Q3-3. 대표 이미지(Featured Image)와 본문 이미지의 차이는?** ⭐
→ **대표 이미지**는 WordPress가 글 목록·SNS 공유·관련 글에서 **썸네일로 사용**하는 이미지입니다. 본문과 별도로 설정해야 하며, 한 글당 1장만 지정 가능합니다. **본문 이미지**는 글 안에 `<img>` 태그로 삽입된 이미지들입니다. 보강 실습에서는 둘 다 같은 이미지로 자동 연결됩니다.

**Q4. 컴퓨터를 끄면 Schedule은?**
→ Docker가 멈추므로 Schedule도 중단됩니다. 24시간 운영을 원하면 **VPS(예: AWS Lightsail, Vultr, 월 $5~10)**로 이전하세요.

**Q5. 6시간 과정과 뭐가 다른가요?**
→ 6시간 과정은 **RSS 트렌드 수집 + 주간 콘텐츠 캘린더 + 다중 AI 교차 검수 + 이미지 SEO**까지 포함합니다. 4시간은 핵심만 다루는 버전이며, 실무 고도화는 후속 과정에서 학습 가능합니다.

**Q6. n8n이 갑자기 느려져요**
→ Docker Desktop Settings → Resources에서 RAM을 6~8GB로 늘려보세요. 또는 동시에 실행되는 워크플로우를 줄이세요.
