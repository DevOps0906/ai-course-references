# 3-1. Excel/Sheets 데이터 분석·집계·차트 및 서술형 요약 

## 1. 엑셀 업무에서 AI를 쓰는 3가지 방법

| 방법 | 하는 일 | 언제 쓰나 |
|---|---|---|
| ① 함수·수식 물어보기 | "이럴 땐 무슨 함수?" → 수식을 받아 내 엑셀에 붙여넣기 | 엑셀은 내가 다루고, 수식만 막힐 때 |
| ② 데이터 통째로 맡기기 | 표/파일을 업로드 → 집계·차트·요약까지 AI가 수행 | 일회성 분석, 빠른 파악 |
| ③ 서술형 변환 | 집계 결과 → 보고서용 문장으로 변환 | 숫자는 나왔는데 글 쓰기 귀찮을 때 |

### 💻 [따라하기 12] 방법 ① — 함수를 '말로' 물어보기

엑셀 함수 이름을 몰라도 됩니다. **상황을 말로** 설명하세요.

```
구글 시트에서 A열에 학과명, B열에 프로그램명, C열에 참여인원이 있어.
"학과별 참여인원 합계"를 E열에 자동으로 구하고 싶어.
① 사용할 수식을 알려주고 ② 그 수식이 무슨 뜻인지 한 줄씩 해석해주고
③ 자주 나는 오류(#N/A 등)와 원인도 알려줘.
```

📌 **핵심정리**: "수식만 줘"가 아니라 **"해석 + 예상 오류"까지 요청**하는 것이 비전공자의 생존 기술입니다. 다음에는 스스로 고칠 수 있게 됩니다.

### 💻 [따라하기 13] 방법 ② — 데이터 통째로 분석 맡기기

아래 실습용 가상 데이터를 프롬프트와 함께 통째로 붙여넣으세요. (실제로는 엑셀/CSV 파일을 첨부해도 됩니다)

```
[역할] 너는 대학 교육성과 데이터 분석가야.
[맥락] 아래는 우리 대학 비교과 프로그램의 상반기 운영 실적이야.
[지시] 다음 4가지를 순서대로 해줘.
 ① 데이터에 이상한 점(오타·중복·빈칸)이 있으면 먼저 지적
 ② 학과별 합계와 프로그램 유형별 평균 만족도 집계표
 ③ 눈에 띄는 특징 3가지 (숫자 근거와 함께)
 ④ 이 결과에 어울리는 차트 종류 추천과 이유

[데이터]
학과,프로그램명,유형,참여인원,만족도
간호학과,AI 리터러시 특강,특강,48,4.7
간호학과,취업 모의면접,취업,32,4.5
유아교육과,AI 리터러시 특강,특강,41,4.6
유아교육과,포트폴리오 캠프,취업,27,4.2
호텔항공과,글로벌 매너 특강,특강,55,4.8
호텔항공과,취업 모의면접,취업,38,4.4
반려동물과,동물병원 실무 특강,특강,29,4.9
반려동물과,취업 모의면접,취업,,4.3
```

**관찰 포인트**: 마지막 행의 **참여인원이 비어 있습니다.** AI가 ①단계에서 이걸 잡아내는지 보세요. 잡아냈다면 → `"빈칸은 30으로 채우고 다시 집계해줘"` 로 이어가세요.

📌 **핵심정리**: 분석 지시 1번은 언제나 **"이상한 점부터 지적해줘"**. 더러운 데이터로 계산하면 깨끗한 거짓말이 나옵니다.

### ✏️ 빈칸 채우기 ⑫

> 1. 데이터를 맡기기 전, 개인정보(이름·학번)는 모듈 1에서 배운 대로 **( ㄱ )** 처리한다.
> 2. 집계를 시키기 전에 먼저 시켜야 할 것은 데이터의 **( ㄴ )** 점검이다.
> 3. AI가 계산한 합계·평균 같은 숫자는 최소 1~2개를 **( ㄷ )** 로 검산한다.

# 3-2. 반복 보고서·대시보드 템플릿 설계 

## 1. 핵심 개념: 고정 영역 vs 변동 영역

매주 쓰는 주간보고를 뜯어보면, 사실 **바뀌는 건 일부**입니다.

| 구분 | 예시 | 처리 방법 |
|---|---|---|
| 🔒 고정 영역 | 문서 제목 틀, 목차, 표 양식, 인사말 | 템플릿에 **박아둠** |
| 🔄 변동 영역 | 이번 주 실적 숫자, 특이사항, 다음 주 계획 | **[자리표시자]** 로 비워둠 |

모듈 2-2에서 배운 [날짜], [링크] 자리표시자 기법의 확장판입니다. **"데이터만 갈아끼우면 완성되는 프롬프트"** 를 만드는 것이 목표입니다.

### 💻 [따라하기 15] 재사용 가능한 주간보고 템플릿 만들기

**STEP 1. 템플릿 생성을 AI에게 맡기기** — 기존에 쓰던 주간보고 1부(또는 아래 상황)를 주고:

```
[맥락] 나는 매주 금요일 "주간 업무보고"를 작성해. 구성은 ①금주 실적 ②특이사항
      ③차주 계획 세 부분이고, 실적은 표로 정리해.
[지시] 앞으로 매주 재사용할 "프롬프트 템플릿"을 만들어줘. 즉, 내가 매주 바뀌는
      데이터만 붙여넣으면 완성 보고서가 나오도록.
[조건] - 바뀌는 부분은 {{금주실적데이터}}, {{특이사항메모}}, {{차주계획메모}} 자리표시자로
      - 보고서 형식·문체·표 양식 지시는 템플릿 안에 고정으로 포함
      - 완성된 템플릿을 코드블록 하나로 출력해줘 (복사해서 보관하게)
```

**STEP 2. 재사용 테스트** — 나온 템플릿을 **새 대화창**에 붙여넣고, {{ }} 자리에 아무 메모나 넣어 실행해 보세요.

```
(예: {{금주실적데이터}} 자리에)
- 수시 입학설명회 2회 진행, 참석 총 87명
- 홍보 SNS 게시물 5건 업로드, 도달 12,400회
- 학과 홍보 영상 촬영 완료 (편집 중)
```

**STEP 3. 통과 기준**: 새 대화창에서도 지난주와 **같은 형식**의 보고서가 나오면 템플릿 합격! 메모장/노션에 저장하세요.

📌 **핵심정리**: 왜 새 대화창에서 테스트하나요? → AI는 **대화가 바뀌면 기억이 초기화**되기 때문입니다(모듈 1 참고). 템플릿은 "기억이 없어도 작동해야" 진짜 템플릿입니다.

### ✏️ 빈칸 채우기 ⑬ — 템플릿 설계 진단

어느 직원이 만든 주간보고 프롬프트 템플릿입니다. 무엇이 문제일까요?

> "지난번처럼 주간보고 써줘. 데이터: {{금주실적데이터}}"

> 문제점 ①: "**( ㄱ )**"은 새 대화창에서는 통하지 않는 지시다. (AI에게는 '지난번'이 없다)
> 문제점 ②: 보고서의 **( ㄴ )** 지시(목차·표 양식·문체)가 템플릿에 고정되어 있지 않아 매번 결과가 달라진다.

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

- **( ㄱ ) "지난번처럼"** — 템플릿에서 금지어 1호입니다. 새 대화창의 AI는 지난번을 모릅니다. 형식 지시를 **템플릿 안에 전부 명시**해야 합니다.
- **( ㄴ ) 형식(Format)** — R-C-T-F-C의 F가 고정 영역에 박혀 있어야 매주 같은 모양이 나옵니다. **"고정 영역 = 형식과 조건, 변동 영역 = 데이터"** 로 기억하세요.
</details>

## 2. 대시보드 설계 — "한 화면 요약"의 원칙

대시보드 = 상급자가 **10초 안에** 현황을 파악하는 한 화면. 구성 3층:

```
[1층] 핵심지표 3~5개 (큰 숫자: 참여인원, 달성률, 만족도, 예산집행률)
[2층] 추이 (월별/주별 변화 — 꺾은선)  +  비교 (학과별/유형별 — 막대)
[3층] 특이사항·조치필요 목록 (글머리 3줄 이내)
```

### 💻 [따라하기 16] 내 업무의 대시보드 설계도 뽑기

```
나는 대학에서 "{{본인 업무: 예) 비교과 프로그램 운영}}" 업무를 담당해.
이 업무의 월간 대시보드를 설계해줘.
[형식] ①핵심지표(KPI) 5개와 각각의 산출식 ②지표별 추천 차트와 이유
      ③구글 시트로 만든다면 시트 구성(원본데이터/집계/대시보드 탭)을 표로
[조건] 실제로 수집 가능한 데이터만 사용할 것. 수집이 어려운 지표는 대안을 제시.
```

→ 설계도가 나오면, 차트 자체는 [따라하기 13]처럼 데이터를 주고 그리게 하거나 시트에서 직접 만듭니다. **AI에게는 '설계'를, 시트에는 '표시'를** 맡기는 분업입니다.

# 3-3. 트리거–액션–LLM 결합 자동화 실습 
### — Make 메인 실습 + Google Workspace Studio·n8n 확장 실습 —

**⏱️ 3-3 시간 구성 (150분)**

| 구간 | 내용 | 시간 |
|---|---|---|
| 개념 | 트리거·액션·LLM 결합, 5대 도구 비교 | 20분 |
| 메인 실습 | [따라하기 17] Make로 행사 신청 자동 접수 시스템 | 60분 |
| 확장 실습 ① | [따라하기 18] Google Workspace Studio — 자연어로 플로우 만들기 | 25분 |
| 확장 실습 ② | [따라하기 19] n8n — 같은 시나리오, 다른 도구 | 25분 |
| 미니 프로젝트 | [따라하기 20] 내 기획서를 자동화 설계로 | 20분 |

## 1. 딱 두 단어만 기억하세요: 트리거와 액션

워크플로 자동화의 문법은 놀랄 만큼 단순합니다.

> **"~하면(트리거) → ~해라(액션)"**

| 용어 | 뜻 | 대학 업무 예시 |
|---|---|---|
| 트리거(Trigger) | 자동화가 **시작되는 사건** | 폼 제출됨 / 메일 도착함 / 매주 금요일 9시 |
| 액션(Action) | 그때 **자동으로 하는 일** | 시트에 기록 / 메일 발송 / 문서 생성 |
| 시나리오(Zap/Flow) | 트리거+액션들을 이은 한 줄기 | 폼 제출 → 시트 기록 → 확인메일 발송 |

**5대 도구 비교** (무엇을 쓰든 트리거–액션 개념은 동일합니다)

| 도구 | 특징 | 이런 경우 추천 |
|---|---|---|
| Zapier | 가장 쉬움, 연동 앱 최다 | 처음 시작, 간단한 연결 |
| Make | 시각적 캔버스, 무료 플랜 넉넉 | 개인 계정 실습·복잡한 분기 (**오늘 메인 도구**) |
| Power Automate | MS365(아웃룩·팀즈·엑셀)와 한몸 | 학교가 MS365 기반이면 1순위 |
| **Google Workspace Studio** | 구글 Workspace에 내장, **Gemini(AI)가 기본 탑재**, 자연어로 플로우 생성 | 학교가 구글 Workspace(Education 등) 조직 계정 기반이면 1순위 |
| **n8n** | 오픈소스, **셀프호스팅 가능**(내 서버에 설치), 자체 폼·AI 에이전트 노드, 코드 확장 | 개인정보를 외부 클라우드에 못 올리는 업무, IT 부서와 협업, 대량·무제한 실행 |

💡 **도구가 5개라고 5배 어려운 게 아닙니다.** 문법(트리거→액션→LLM)은 하나이고, 도구는 사투리 차이일 뿐입니다. 오늘 Make로 완주한 뒤, 같은 시나리오를 Workspace Studio와 n8n으로 다시 만들어 보며 이를 직접 확인합니다.

### ✏️ 빈칸 채우기 ⑭ — 트리거? 액션?

다음에서 트리거(T)와 액션(A)을 구분하세요.

> 1. 구글폼으로 행사 신청이 제출되면 **(  )** → 신청자 시트에 한 줄 추가 **(  )** → 신청자에게 확인 메일 발송 **(  )**
> 2. 매주 금요일 오후 4시가 되면 **(  )** → 이번 주 실적 시트를 읽어 **(  )** → 요약 메일을 팀장에게 발송 **(  )**

<details>
<summary>👉 <b>[해설] 정답 확인</b></summary>

1. **T → A → A** / 2. **T → A → A**

💡 포인트 두 가지:
- 트리거는 시나리오당 **1개(맨 앞)**, 액션은 여러 개를 이을 수 있습니다.
- 2번처럼 **"시간"도 트리거**가 됩니다(스케줄 트리거). 사건이 없어도 정기 보고를 자동화할 수 있는 이유입니다.

## 2. LLM을 끼워 넣으면 '생각하는 자동화'가 된다

트리거–액션만으로는 **옮기기**만 가능합니다. 중간에 AI(LLM) 모듈을 넣으면 **읽고·판단하고·써주는** 단계가 생깁니다.

```
[기본 자동화]   폼 제출 → 시트 기록 → 접수 확인 메일(전원 동일한 문구)
[LLM 결합]     폼 제출 → 시트 기록 → ✨AI가 문의 내용을 읽고 유형 분류 + 맞춤 답변 초안 작성✨
               → 답변이 담긴 메일 발송 (또는 담당자에게 초안 전달)
```

모듈 1 빈칸 ②의 4번 문제("민원 분류+답변 초안")가 바로 이 구조였습니다. 오늘 직접 만듭니다.

## 3. 💻 [따라하기 17] 메인 실습: "행사 신청 자동 접수 시스템" 만들기 — Make 기준 

**완성 목표**: `구글폼 제출(T) → 구글시트 기록(A) → AI가 확인 메일 문안 생성(LLM) → 신청자에게 자동 발송(A)`

> ⚙️ 사전 준비: 구글 계정, Make(make.com) 무료 계정, AI API 또는 Make 내 AI 모듈 (계정 세팅 가이드는 별도 배포 / 협회 지원 도구 확정 시 변경될 수 있습니다)

### STEP 1. 구글폼 만들기 
1. 구글폼 새로 만들기 → 제목: "교내 AI 특강 신청"
2. 질문 4개: 이름(단답) / 이메일(단답) / 소속 학과(드롭다운) / 문의사항(장문, 선택)
3. 응답 탭 → **스프레드시트에 연결** (이 시트가 우리의 데이터베이스가 됩니다)

### STEP 2. Make에서 시나리오 만들기 
1. Make 로그인 → **Create a new scenario**
2. 첫 모듈(트리거) 추가: **Google Sheets → Watch New Rows** 선택 → STEP 1의 응답 시트 연결
   - 💡 왜 폼이 아니라 시트를 지켜보나요? → 폼 응답은 어차피 시트에 쌓이므로, **시트에 새 줄이 생기는 것**을 트리거로 잡는 게 가장 간단하고 어느 도구에서나 통하는 방식입니다.
3. **폼에서 테스트 응답 1건을 직접 제출**한 뒤, Make에서 "Run once"로 데이터가 들어오는지 확인
   - 이름·이메일·학과가 항목별로 잡히면 성공! ✅

### STEP 3. AI(LLM) 모듈 끼우기 
1. 두 번째 모듈 추가: AI 모듈 (Make의 OpenAI/Anthropic 모듈 등 — 당일 안내되는 도구 사용)
2. 프롬프트 칸에 아래를 입력하되, `{{ }}` 부분은 **타이핑하지 말고** 앞 모듈에서 넘어온 데이터 항목을 클릭해서 끼워 넣습니다:

```
[역할] 너는 대학 행사 담당 직원이야.
[지시] 아래 신청자에게 보낼 접수 확인 메일 본문을 작성해줘.
[신청 정보] 이름: {{이름}} / 학과: {{학과}} / 문의사항: {{문의사항}}
[조건] - 5문장 이내, 공손한 존댓말
      - 행사 일시(8/28 목 14시, 대강당)와 준비물(학생증) 안내 포함
      - 문의사항이 있으면 그에 대한 답을 한 문장 포함하고, 확답이 어려운 내용이면
        "담당자가 확인 후 회신드리겠습니다"로 안내
      - 메일 본문만 출력 (제목, 인사말 외 설명 금지)
```

3. "Run once" → AI가 만든 문안이 출력되는지 확인. **문의사항을 다르게 넣어 2~3번 테스트**해 보세요. 매번 맞춤 답변이 나오는 것이 LLM 결합의 힘입니다.

### STEP 4. 메일 발송 모듈 연결 
1. 세 번째 모듈: **Gmail(또는 Email) → Send an Email**
2. 받는사람 = `{{이메일}}` (앞 모듈 데이터 클릭), 제목 = "[계명문화대] AI 특강 신청이 접수되었습니다", 본문 = `{{AI 모듈의 출력}}`
3. **⚠️ 중요: 받는사람을 본인 메일로 바꿔서 먼저 테스트!** 실제 신청자에게 실험 메일이 가면 안 됩니다.

### STEP 5. 가동 및 검증 
1. 시나리오 좌하단 스위치 **ON** (스케줄: 15분마다 확인 등)
2. 폼에서 신규 제출 → 몇 분 내에 ①시트에 기록 ②내 메일함에 AI 맞춤 확인 메일 도착 확인
3. 🎉 **축하합니다. 여러분의 첫 무인 자동화 시스템이 가동 중입니다.**

|---|---|---|

## 4. 💻 [따라하기 18] 확장 실습 ①: Google Workspace Studio — "말로 만드는 자동화" 

> ⚙️ **사전 조건**: Workspace Studio는 Gemini가 포함된 **Google Workspace 조직 계정**(Business/Enterprise, 교육기관은 Education 에디션)에서 사용할 수 있습니다. 개인 무료 Gmail 계정으로는 접속되지 않습니다.
> **조직 계정이 없는 분은 강사 화면 데모를 보며 [관찰 포인트]와 [빈칸 ⑯]에 집중해 주세요.** (우리 학교가 구글 기반이라면, 연수 후 실무에서는 이 도구가 1순위가 됩니다.)

**Workspace Studio가 뭐가 다른가?** — Make에서는 우리가 모듈을 하나하나 손으로 이었습니다. Workspace Studio는 **하고 싶은 일을 한국어 문장으로 설명하면 Gemini가 플로우의 골격을 만들어 줍니다.** 또 AI(Gemini)가 별도 연결 없이 **처음부터 단계 안에 내장**되어 있고, Gmail·Drive·Chat 연동에 계정 연결 절차가 거의 없습니다(이미 같은 구글 계정이니까요).

### STEP 1. 접속 
1. `studio.workspace.google.com` 접속 (또는 Gmail 우측 상단 Gemini 아이콘 근처의 Studio 바로가기)
2. 첫 화면에서 **템플릿 갤러리**와 **직접 만들기(자연어 입력)** 를 확인합니다.

### STEP 2. 자연어로 플로우 골격 생성 
입력창에 [따라하기 17]에서 만든 것과 같은 시나리오를 **문장으로** 설명합니다:

```
구글폼 "교내 AI 특강 신청"의 응답이 스프레드시트에 추가되면,
Gemini가 신청자의 이름·학과·문의사항을 참고해 접수 확인 메일 문안을 작성하고,
신청자의 이메일 주소로 Gmail을 발송해줘.
```

→ Gemini가 **[시작 이벤트(트리거)] → [Gemini 단계] → [Gmail 발송 단계]** 골격을 자동 생성합니다.

**관찰 포인트 🔍**: 생성된 골격을 뜯어보세요. 이름만 다를 뿐 — 시작 이벤트=트리거, 단계=액션 — **Make에서 배운 구조가 그대로**입니다. 도구가 바뀌어도 문법은 하나라는 것을 눈으로 확인하는 순간입니다.

### STEP 3. Gemini 단계 다듬기 
1. 자동 생성된 Gemini 단계를 열고, 프롬프트를 **[따라하기 17] STEP 3의 프롬프트로 교체**합니다. (프롬프트 카드는 도구를 가리지 않고 재사용됩니다!)
2. 신청자 정보(이름·학과·문의사항)는 앞 단계의 데이터 항목을 선택해 끼워 넣습니다. — Make의 {{ }}와 같은 원리입니다.
3. 받는사람을 **본인 메일로 바꿔** 테스트 실행 → 확인 후 저장·활성화.

### 특징 정리 — 언제 Workspace Studio를 쓰나

| 강점 👍 | 한계 👀 |
|---|---|
| 자연어로 골격 생성 → 진입장벽 최저 | Gemini 포함 Workspace **유료 조직 계정** 필요 |
| Gemini(AI) 기본 내장, 별도 AI 연결 불필요 | 외부(비구글) 앱 연동은 Make·n8n보다 아직 제한적 |
| 구글 앱 간 계정 연결 절차 최소화, 조직 관리자가 보안 통제 | 신생 도구라 기능·화면이 빠르게 바뀌는 중 |

📌 **핵심정리**: 화면 구성은 업데이트로 달라질 수 있습니다. 그래도 당황하지 마세요 — **트리거를 찾고, AI 단계에 프롬프트를 넣고, 액션을 잇는다.** 이 순서는 변하지 않습니다.

## 5. 💻 [따라하기 19] 확장 실습 ②: n8n — "폼까지 자체 제작하는 오픈소스 자동화" 

**n8n이 뭐가 다른가?** — <b>오픈소스</b>라서 학교 서버에 직접 설치(셀프호스팅)할 수 있습니다. 즉, **데이터가 외부 클라우드로 나가지 않는 자동화**가 가능해, 개인정보·내부 자료를 다루는 기관 업무에 강점이 있습니다. 또 구글폼 없이 **n8n 자체에서 접수 폼을 만들 수 있고**, 수백 개 앱 연동과 AI 에이전트 노드를 지원합니다.

> ⚙️ **사전 준비**: 실습은 **n8n Cloud 무료 체험 계정**으로 진행합니다(가입만 하면 바로 사용, 설치 불필요). 참고로 실무 도입 시에는 IT 부서와 협의해 교내 서버에 Docker로 셀프호스팅하는 방식이 일반적입니다 — 이건 전산 담당자의 영역이니 "그런 옵션이 있다"만 기억하세요.

이번에는 같은 시나리오를 **구글폼 없이** n8n만으로 만들어 봅니다.

### STEP 1. 트리거: n8n 자체 폼 만들기 
1. 로그인 → **New Workflow** → 첫 노드 추가에서 **"On form submission" (n8n Form Trigger)** 선택
2. 폼 제목 "교내 AI 특강 신청", 필드 4개 추가: 이름 / 이메일 / 소속 학과 / 문의사항
3. 노드가 만들어주는 **폼 URL**을 복사해 새 탭에서 열어보세요 — 방금 접수 페이지가 생겼습니다! (구글폼+시트 역할을 노드 하나가 대신)

### STEP 2. AI 노드 연결 
1. 다음 노드로 **AI 노드**(OpenAI / Gemini / Anthropic 등 — 당일 안내되는 도구의 노드)를 추가
2. 프롬프트 칸에 **[따라하기 17] STEP 3의 프롬프트를 그대로** 붙여넣고, 이름·학과·문의사항 자리는 왼쪽 패널의 폼 데이터 항목을 **드래그해서** 끼워 넣습니다. (세 번째 도구에서도 원리는 동일 — 이제 몸이 기억하죠?)
3. 테스트 실행으로 AI 문안이 출력되는지 확인.

### STEP 3. 발송 + 가동 
1. **Gmail → Send a message** 노드 추가: 받는사람=폼의 이메일 항목, 본문=AI 노드 출력
2. ⚠️ 철칙 그대로: **받는사람을 본인 메일로 바꿔 먼저 테스트**
3. 우상단 **Active** 스위치 ON → 폼 URL에서 신규 제출 → 메일 도착 확인 🎉
4. (여유가 되면) 캔버스에서 AI 노드 앞에 **IF 노드**를 끼워 "문의사항이 비어 있으면 표준 문안, 있으면 AI 맞춤 문안"으로 분기시켜 보세요 — n8n의 유연함을 맛볼 수 있습니다.

### 세 도구를 모두 써본 소감 정리 — 오늘의 최종 비교

| | Make | Workspace Studio | n8n |
|---|---|---|---|
| 폼 | 구글폼 별도 연결 | 구글폼 (같은 계정이라 연결 간편) | **자체 폼 내장** |
| AI 연결 | AI 모듈 추가 연결 | **Gemini 기본 내장** | AI 노드 추가 연결 (선택지 다양) |

## 6. 💻 [따라하기 20] 응용 : 내 기획서를 자동화로 (미니 프로젝트)

```
아래는 내 업무 자동화 기획서의 TO-BE 부분이야. 이것을 워크플로 자동화 도구로
구현한다면 [트리거 → 액션 → AI 처리 → 액션] 흐름으로 설계해줘.

무료 플랜으로 어려운 부분이 있으면 대안도 알려줘.
[기획서 TO-BE 붙여넣기]
```

## 7. 운영 시 주의사항 — 자동화에도 브레이크가 필요합니다

1. **사람 검토 지점(Human-in-the-loop)**: 외부 발송·금액·성적 관련은 "자동 발송" 대신 **"초안을 담당자에게 발송"** 으로 설계하세요. AI 초안 원칙(모듈 1)은 자동화에서도 유효합니다.
2. **개인정보**: 자동화에 흐르는 데이터도 개인정보입니다. 불필요한 항목은 수집하지 않고, AI 모듈에는 필요한 최소 항목만 전달하세요.
3. **실패 알림**: 시나리오 오류 시 나에게 알림이 오도록 설정(도구별 Error handler) — 조용히 멈춰 있는 자동화가 가장 위험합니다.
4. **무료 플랜 한도**: 월 작업 횟수 제한이 있으니, 대량 발송 업무는 한도를 먼저 확인하세요.

**1. 엑셀 AI 3법**: 함수는 "해석+오류까지" · 분석은 "이상치 점검부터" · 숫자는 "표본 검산"

**2. 템플릿 공식**: 고정 영역(형식·조건) + 변동 영역({{자리표시자}}) / 금지어: "지난번처럼"

**3. 자동화 문법**: ~하면(트리거 1개) → ~해라(액션 여러 개), 시간도 트리거다

**4. LLM 결합**: 옮기기(자동화) + 읽고 쓰기(AI) = 생각하는 자동화

**5. 자동화 철칙 3**: 나에게 먼저 발송 · 민감 업무는 초안까지만 · 실패 알림 설정

**6. 도구 선택 공식**: 구글 조직=Workspace Studio · MS 조직=Power Automate · 개인 계정 연습=Make/Zapier · 보안·교내 서버=n8n(셀프호스팅) — 문법은 어차피 하나!

**7. 최종 산출물**: 동작하는 시나리오 1개(3개 도구 중 택1 이상) + 내 기획서의 자동화 설계안 ✅
