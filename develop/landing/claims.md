# 랜딩 주장 근거 목록

'검증' 상태인 주장만 landing.json에서 claim ID로 참조할 수 있다 (build.py의 lint_landing이 검사).
'보류' 주장은 화면에 '준비 중' 태그로만 표시하고 claim ID로 인용하지 않는다. 기능이 출시되고 확인된 뒤에 '검증'으로 바꾼다.

| ID | 주장 | 근거 | 상태 |
|---|---|---|---|
| C1 | 과정·은행·문항 수는 빌드 때 실제 은행 파일에서 자동 계산한 값이다 | build.py collect_catalog()가 dist에 실제로 만들어진 은행만 세어 totals를 만든다 | 검증 |
| C2 | 풀면 즉시 채점되고, 문항마다 원문 위치를 알려 주는 힌트가 붙는다 | quiz.html 즉시 채점 동작, 은행 JSON의 문항 h 필드(validate.py가 필수로 검사) | 검증 |
| C3 | 틀린 문제는 자동으로 오답 목록에 기록되고 다시 풀 수 있다 | quiz.html의 qb:<은행>:v1 wrong 기록, 대시보드 남은 오답 화면 | 검증 |
| C4 | 타임어택 제한 시간을 5·7·10·15초 중 고를 수 있다 | quiz.html 게임 모드 설정 | 검증 |
| C5 | 설치나 서버 없이 HTML 파일을 열면 바로 풀 수 있다 | 정적 HTML 단일 파일 빌드, file:// 로 열어 확인 | 검증 |
| C6 | 보기 번호를 말로 고를 수 있다 (Chrome·Edge) | design/qb-voice.js 구현 중. 출시와 실제 브라우저 확인 뒤 검증으로 바꾼다 | 보류 |
| C7 | 내 PDF를 올리면 문제가 자동으로 만들어진다 | 업로드부터 자동 출제까지 이어지는 기능이 아직 없다 | 보류 |
| C8 | 스캔 이미지 속 글자를 OCR로 읽는다 | ingest.py에 OCR이 없다 | 보류 |
| C9 | 국어·영어·과학·음악·미술 문제은행을 제공한다 | 스키마만 준비됨, 해당 과목 은행 없음 | 보류 |
