# 개발서 — Quiz Bank

> 기획은 [`plan/`](../plan), 디자인은 [`design/`](../design)에 있다. 이 문서는 **구조, 데이터, 명령어, 확장 방법**을 다룬다.

## 1. 폴더
```
develop/
├─ 개발서.md                 ← 이 문서
├─ ingest.py                 ① 수집: pdf·docx·txt·md·ipynb → 출제용 md
├─ sources/                  ① 결과 (ingest 출력, 자동 생성)
├─ prompts/출제_프롬프트.md   ③ 출제 지시문 (Claude Code / 이후 API 공용)
├─ schema/bank.schema.json   ② 문제은행 형식
├─ banks/<폴더>/<이름>.json   ③ 문제은행 (콘텐츠의 유일한 원천)
├─ validate.py               ④ 검증
├─ engine/quiz.html          ⑤ 엔진 템플릿 (화면·채점·저장·게임)
├─ build.py                  ⑤ 엔진 + design/tokens.css + 은행 → 단일 HTML
└─ dist/<폴더>/<이름>.html    ⑤ 결과 페이지 (빌드 산출물)
```
`design/tokens.css`는 빌드할 때 엔진 `<style>` 맨 앞에 들어간다. 색과 형태를 바꾸려면 토큰만 고치고 다시 빌드한다.

## 2. 명령어
| 목적 | 명령 |
|---|---|
| 문서 → md | `python develop/ingest.py <문서> [-o out.md]` |
| 검증 (전체/하나) | `python develop/validate.py [bank.json]` |
| 빌드 (전체/하나) | `python develop/build.py [bank.json]` — 끝에 허브 `dist/index.html`을 항상 다시 만든다(과정 이름은 `build.py`의 `STAGES`) |
| 금지어 검사 | `python tools/check.py` |
| 로컬에서 보기 | `dist/…/*.html` 더블클릭 (서버 불필요) |

Windows 콘솔에서 한글이 깨지면 `set PYTHONIOENCODING=utf-8`(PowerShell: `$env:PYTHONIOENCODING='utf-8'`)을 먼저 실행한다.

PDF 추출은 pymupdf → pypdf → pdftotext 순서로 설치된 것을 쓴다. 글자 층이 없거나 깨진 PDF(스캔본, 일부 폰트 재삽입본)는 경고를 내며, OCR은 4단계 과제다.

## 3. 새 자료 추가 절차
1. pdf·docx·txt 자료라면 `ingest.py`로 md를 만든다. md 자료는 바로 쓴다.
2. Claude Code에 [`prompts/출제_프롬프트.md`](prompts/출제_프롬프트.md)를 주고 은행 JSON을 만들게 한다. 저장 위치는 `banks/<원본 폴더 구조>/<이름>.json`이다.
3. `validate.py`에서 ✗가 0이 되게 하고, `plan/03_출제기준.md` §5 체크리스트로 사람이 검수한다.
4. `build.py` → `tools/check.py`를 돌린다.
5. 브라우저로 탭 1개를 풀고 게임 1판을 해 본다.
6. 루트 README의 '문제은행' 표와 CHANGELOG를 갱신한다.

## 4. 데이터 형식
스키마는 [`schema/bank.schema.json`](schema/bank.schema.json)에 있다. 유형별 정답 표기는 다음과 같다.

| ty | 필드 | 정답 | 화면 |
|---|---|---|---|
| mc | `o[]` | `a`: 인덱스 | 라디오 |
| multi | `o[]` | `a`: 인덱스 배열 | 체크박스 |
| ox | — | `a`: true/false | O·X 버튼 |
| match | `pairs[[L,R]]` | 작성 순서가 정답 | 오른쪽 섞음, 클릭으로 짝 지정 (같은 글자·색 표시) |
| order | `steps[]` | 작성 순서가 정답 | 항목 위치는 섞어서 고정. **클릭한 순서대로 번호**가 붙음. 번호 붙은 항목을 다시 누르면 그 번호부터 뒤 번호 모두 삭제(1번 → 전체 리셋). 답 = 클릭 순서의 단계 인덱스 배열 |
| num | `unit`, `tol` | `a`: 숫자 | 입력칸 |

voice-ai 워크시트(D2~7) 형식과의 차이: match는 `left/right/a` 대신 `pairs`, order는 `steps+a` 대신 '정답 순서로 쓴 steps'를 쓴다. 출제자가 정답 인덱스를 손으로 계산하지 않아도 되게 한 것이다. 이관 스크립트는 이 차이만 변환하면 된다.

## 5. 엔진 구조 (`engine/quiz.html`)
단일 HTML이고 외부 JS는 없다(Google Fonts만 쓴다). 스크립트는 IIFE 하나에 다음 구역으로 나뉜다.

| 구역 | 내용 |
|---|---|
| 상수·인덱스 | `TYPES`, `GUIDE`, `GAME_MODES`(게임 모드 목록), `GAME_SLOTS`(선택 화면 3칸), `QMAP`/`QTAB` |
| 저장소 | `S = {name, tabs, wrong, board}` → `localStorage['qb:<bank.id>:v1']`, 모든 접근을 try/catch로 감쌈 |
| `Leaderboard` | `load()`, `add(rec) → 순위`. **공유 순위로 바꿀 때 이 객체만 교체** |
| 채점 | `isCorrect`, `correctText`, `answerText` |
| 오답노트 | `addWrong`, `markSolved`, `wrongList` |
| 풀이 시트 | `newSheet`, `cardHTML`, `refreshCard`, `gradeSheet`. 학습 모드와 오답 재도전이 같이 씀 |
| 화면 | `viewHome / viewStudy / viewSummary / viewNotes / viewRetry / viewKey / viewGameSetup` |
| 게임 | `startGame → renderGameQ → tick(rAF) → judge → finishGame` |
| 라우터 | `#home`, `#study/<tab>`, `#summary`, `#notes`, `#retry`, `#key`, `#game` |

**저장 데이터**
```js
S.tabs[tabId]  = {score,total,answers:{qid:ans},touched:[qid],at}   // 채점한 탭 (게임·해설지 잠금 해제 근거)
S.wrong[qid]   = {n,last,at,solved}                                  // 오답노트
S.board[]      = {id,name,score,correct,total,rate,avg,combo,at}     // 순위 (상위 50개 보관)
S.drafts[tabId] = {qid:ans}                                          // 채점 전 풀던 답 (탭 이동·새로고침 후 이어 풀기, 채점 시 삭제)
```

**게임 모드 구조** — 게임은 계속 추가된다
- `#game` → `viewGamePick()`: `GAME_SLOTS = ['timeattack', null, null]` 3칸 버튼. `null`은 "준비 중".
- `#game/<modeId>` → `viewGameSetup(modeId)`: `GAME_MODES[modeId]`의 설정으로 화면을 그린다.
- **새 게임 추가 절차**: ① `GAME_MODES`에 `{title, desc, types, …설정}` 추가 ② `GAME_SLOTS`의 `null` 자리에 id 넣기 ③ 진행 방식이 다르면 시작·판정 함수를 모드별로 분기.
- 순위 기록에는 `mode`, `time`이 들어가고, `Leaderboard.load(key)`는 `key = "mode:time"`이 같은 기록만 비교한다(조건별 상위 50개 보관).

**타임어택 규칙**
- 풀이 시간은 `GAME_MODES.timeattack.times = [5, 7, 10, 15]`초 중 선택하며, 모든 문항에 똑같이 적용한다(기본 10초).
- 점수는 `(100 + 남은 0.1초 단위) × 콤보 배수`다. 3연속부터 ×1.2, 5연속부터 ×1.5를 곱한다.
- 탭이 백그라운드에 있으면 rAF가 멈추므로 타이머도 멈춘다. 다시 보일 때 `G.last`를 초기화한다.
- `prefers-reduced-motion`이면 타이머 바를 1초 단위로 줄인다.

## 6. 확장 지점 (로드맵 연결)
| 단계 | 작업 | 손댈 곳 |
|---|---|---|
| 3 출제 자동화 | `generate.py`: ingest md → Claude API(`claude-opus-5-5`) → JSON → validate 실패 시 재시도 | 새 파일 하나. 지시문은 `prompts/` 재사용 |
| 4 분석 자동화 | `outline.json`(단원·개념·근거 위치) 먼저 생성 → 탭별 출제 | ingest와 generate 사이에 단계 추가 |
| 4 2차 검수 | 문항마다 근거 문장 인용 요청 → 근거 없는 문항 표시 | validate에 `--ai` 옵션 |
| 5 공유 순위 | `Leaderboard`를 서버/Artifact DB 구현으로 교체 | 엔진의 `Leaderboard` 객체 |
| 5 웹앱 | 문서 업로드 → 서버에서 ①~⑤ 실행 → 내 문제은행 목록 | 엔진은 그대로, 은행 JSON을 fetch로 받도록 분기 |
| voice-ai 이관 | D1~D7 `const Q` → 은행 JSON 변환 스크립트 | `tools/` 또는 `develop/migrate_voice.py` |
