# 개발서 — Quiz Bank

> 기획은 [`plan/`](../plan), 디자인은 [`design/`](../design)에 있다. 이 문서는 **구조, 데이터, 명령어, 확장 방법**을 다룬다.

## 1. 폴더
```
develop/
├─ 개발서.md                 ← 이 문서
├─ ingest.py                 ① 수집: pdf·docx·txt·md·ipynb → 출제용 md
├─ sources/                  ① 결과 (ingest 출력, 자동 생성)
├─ prompts/출제_프롬프트.md   ③ 출제 지시문 (Claude Code / 이후 API 공용)
├─ schema/bank.schema.json   ② 문제은행 형식
├─ banks/<폴더>/<이름>.json   ③ 문제은행 (콘텐츠의 유일한 원천)
├─ validate.py               ④ 검증
├─ engine/quiz.html          ⑤ 문제은행 템플릿 (화면·채점·저장·게임·음성)
├─ engine/landing.html       ⑤ 랜딩 템플릿 → dist/index.html
├─ engine/login.html         ⑤ 체험 로그인 템플릿 → dist/login.html
├─ engine/dashboard.html     ⑤ 대시보드 템플릿 → dist/dashboard.html (예전 hub.html)
├─ landing/landing.json      랜딩 문구·데이터 / landing/claims.md 주장 근거 목록
├─ build.py                  ⑤ 템플릿 + design/ 산출물 + 은행 → 단일 HTML
└─ dist/                     ⑤ 결과: index·login·dashboard.html + <폴더>/<이름>.html (빌드 산출물)
```
`design/tokens.css`(토큰 v3)와 `components.css`·`icons.svg`·`qb-*.js`는 빌드할 때 각 템플릿의 자리표시자에 들어간다(§8). 색과 형태를 바꾸려면 토큰만 고치고 다시 빌드한다.

## 2. 명령어
| 목적 | 명령 |
|---|---|
| 문서 → md | `python develop/ingest.py <문서> [-o out.md]` |
| 검증 (전체/하나) | `python develop/validate.py [bank.json]` |
| 빌드 (전체/하나) | `python develop/build.py [bank.json]` — 끝에 랜딩·로그인·대시보드를 항상 다시 만든다(과정 이름·과목은 `build.py`의 `STAGES`) |
| 금지어 검사 | `python tools/check.py` |
| 로컬에서 보기 | `dist/…/*.html` 더블클릭 (서버 불필요) |

Windows 콘솔에서 한글이 깨지면 `set PYTHONIOENCODING=utf-8`(PowerShell: `$env:PYTHONIOENCODING='utf-8'`)을 먼저 실행한다.

PDF 추출은 pymupdf → pypdf → pdftotext 순서로 설치된 것을 쓴다. 글자 층이 없거나 깨진 PDF(스캔본, 일부 폰트 재삽입본)는 경고를 내며, OCR은 아직 없다(§12 로드맵).

## 3. 새 자료 추가 절차
1. pdf·docx·txt 자료라면 `ingest.py`로 md를 만든다. md 자료는 바로 쓴다.
2. Claude Code에 [`prompts/출제_프롬프트.md`](prompts/출제_프롬프트.md)를 주고 은행 JSON을 만들게 한다. 저장 위치는 `banks/<과정 id 구조>/<이름>.json`이다(`banks/`·`dist/`는 `04-voice-ai` 같은 단계 id 구조이고, 원본 과정 폴더는 레포 루트의 `source/`에 있다).
   은행 JSON의 `source` 필드와 `rag_sources.json`의 glob은 `source/` 기준 상대경로다(`rag.py`의 `SRC_ROOT`).
3. `validate.py`에서 ✗가 0이 되게 하고, `plan/03_출제기준.md` §5 체크리스트로 사람이 검수한다.
4. `build.py` → `tools/check.py`를 돌린다.
5. 브라우저로 탭 1개를 풀고 게임 1판을 해 본다.
6. 루트 README의 '문제은행' 표와 CHANGELOG를 갱신한다.

## 4. 데이터 형식
스키마는 [`schema/bank.schema.json`](schema/bank.schema.json)에 있다. 유형별 정답 표기는 다음과 같다.

| ty | 필드 | 정답 | 화면 |
|---|---|---|---|
| mc | `o[]` | `a`: 인덱스 | 라디오 |
| multi | `o[]` | `a`: 인덱스 배열 | 체크박스 |
| ox | — | `a`: true/false | O·X 버튼 |
| match | `pairs[[L,R]]` | 작성 순서가 정답 | 오른쪽 섞음, 클릭으로 짝 지정 (같은 글자·색 표시) |
| order | `steps[]` | 작성 순서가 정답 | 항목 위치는 섞어서 고정. **클릭한 순서대로 번호**가 붙음. 번호 붙은 항목을 다시 누르면 그 번호부터 뒤 번호 모두 삭제(1번 → 전체 리셋). 답 = 클릭 순서의 단계 인덱스 배열 |
| num | `unit`, `tol` | `a`: 숫자 | 입력칸 |

voice-ai 워크시트(D2~7) 형식과의 차이: match는 `left/right/a` 대신 `pairs`, order는 `steps+a` 대신 '정답 순서로 쓴 steps'를 쓴다. 출제자가 정답 인덱스를 손으로 계산하지 않아도 되게 한 것이다. 이관 스크립트는 이 차이만 변환하면 된다.

## 5. 엔진 구조 (`engine/quiz.html`)
단일 HTML이고 외부 JS는 없다(Google Fonts만 쓴다). 스크립트는 IIFE 하나에 다음 구역으로 나뉜다.

| 구역 | 내용 |
|---|---|
| 상수·인덱스 | `TYPES`, `GUIDE`, `GAME_MODES`(게임 모드 목록), `GAME_SLOTS`(선택 화면 3칸), `QMAP`/`QTAB` |
| 저장소 | `S = {name, tabs, wrong, board}` → `localStorage['qb:<bank.id>:v1']`, 모든 접근을 try/catch로 감쌈 |
| `Leaderboard` | `load()`, `add(rec) → 순위`. **공유 순위로 바꿀 때 이 객체만 교체** |
| 채점 | `isCorrect`, `correctText`, `answerText` |
| 오답노트 | `addWrong`, `markSolved`, `wrongList` |
| 풀이 시트 | `newSheet`, `cardHTML`, `refreshCard`, `gradeSheet`. 학습 모드와 오답 재도전이 같이 씀 |
| 화면 | `viewHome / viewStudy / viewSummary / viewNotes / viewRetry / viewKey / viewGameSetup` |
| 게임 | `startGame → renderGameQ → tick(rAF) → judge → finishGame` |
| 라우터 | `#home`, `#study/<tab>`, `#summary`, `#notes`, `#retry`, `#key`, `#game` |

**저장 데이터**
```js
S.tabs[tabId]  = {score,total,answers:{qid:ans},touched:[qid],at}   // 채점한 탭 (게임·해설지 잠금 해제 근거)
S.wrong[qid]   = {n,last,at,solved}                                  // 오답노트
S.board[]      = {id,name,score,correct,total,rate,avg,combo,at}     // 순위 (상위 50개 보관)
S.drafts[tabId] = {qid:ans}                                          // 채점 전 풀던 답 (탭 이동·새로고침 후 이어 풀기, 채점 시 삭제)
```

**게임 모드 구조** — 게임은 계속 추가된다
- `#game` → `viewGamePick()`: `GAME_SLOTS = ['timeattack', null, null]` 3칸 버튼. `null`은 "준비 중".
- `#game/<modeId>` → `viewGameSetup(modeId)`: `GAME_MODES[modeId]`의 설정으로 화면을 그린다.
- **새 게임 추가 절차**: ① `GAME_MODES`에 `{title, desc, types, …설정}` 추가 ② `GAME_SLOTS`의 `null` 자리에 id 넣기 ③ 진행 방식이 다르면 시작·판정 함수를 모드별로 분기.
- 순위 기록에는 `mode`, `time`이 들어가고, `Leaderboard.load(key)`는 `key = "mode:time"`이 같은 기록만 비교한다(조건별 상위 50개 보관).

**타임어택 규칙**
- 풀이 시간은 `GAME_MODES.timeattack.times = [5, 7, 10, 15]`초 중 선택하며, 모든 문항에 똑같이 적용한다(기본 10초).
- 점수는 `(100 + 남은 0.1초 단위) × 콤보 배수`다. 3연속부터 ×1.2, 5연속부터 ×1.5를 곱한다.
- 탭이 백그라운드에 있으면 rAF가 멈추므로 타이머도 멈춘다. 다시 보일 때 `G.last`를 초기화한다.
- `prefers-reduced-motion`이면 타이머 바를 1초 단위로 줄인다.

## 8. 빌드 구조: 템플릿과 자리표시자
`build.py`는 템플릿 4개를 채워 만든다. 자리표시자가 템플릿에 없으면 빌드가 멈춘다(`fill`).

| 자리표시자 | 내용 | 쓰는 템플릿 |
|---|---|---|
| `/*__TOKENS__*/` | `design/tokens.css` | quiz · landing · login · dashboard |
| `/*__COMPONENTS__*/` | `design/components.css` | landing · login · dashboard (quiz 제외) |
| `<!--__ICONS__-->` | `design/icons.svg` 스프라이트 | landing · login · dashboard |
| `/*__CORE__*/` | `design/qb-core.js` (로그인·테마·과목) | 4개 모두 |
| `/*__PROGRESS__*/` | `design/qb-progress.js` (연속일·히트맵·XP) | dashboard |
| `/*__VOICE__*/` | `design/qb-voice.js` (음성 선택·읽기) | quiz · landing |
| `/*__BANK__*/null` | 은행 JSON | quiz |
| `/*__CATALOG__*/null` | `collect_catalog()` 결과(단계·과목·합계) | landing · dashboard |
| `/*__DEMO__*/null` | `sample_demo()` 데모 문항 | landing |
| `/*__LANDING__*/null` | `landing/landing.json` | landing |
| `__TITLE__` | 페이지 제목 | 4개 모두 |
| `__HUB__`, `__HUBSTAGE__` | 대시보드 상대 경로, `dashboard.html#NN` | quiz |

**산출물**: `dist/<단계>/<이름>.html`(은행별), `dist/index.html`(랜딩), `dist/login.html`, `dist/dashboard.html`. 카탈로그는 dist에 실제로 만들어진 은행만 센다.

**`lint_landing`** (실패하면 빌드 종료 코드 1)
- `claim`·`claims` 키의 ID는 `landing/claims.md`에서 상태가 '검증'이어야 한다. '보류' 주장은 화면에 '준비 중' 태그로만 쓰고 ID로 인용하지 않는다.
- 비교표(`table`)의 우리 칸에 △·✕가 하나 이상 있어야 한다.
- 문구 끝에 '→'를 붙이지 않는다.
- claims.md 작업 순서: 기능을 출시하고 실제로 확인한 뒤 해당 행을 '검증'으로 바꾸고, 그 다음에야 landing.json에서 ID로 인용한다.

**잔여 이름 검사** (`LEFTOVER`): 만든 index·login·dashboard에 벤치마킹 대상 서비스 이름이 남아 있으면 빌드가 실패한다. 비교 대상은 회사명 없이 유형으로만 적는다. 패턴 메모는 [`design/benchmark/patterns.md`](../design/benchmark/patterns.md)에 추상화해서만 둔다.

## 9. 저장 계약 (`design/qb-core.js`)
| 키 | 값 | 비고 |
|---|---|---|
| `qb:user` | `{v:1, name, email, provider, createdAt, lastLoginAt}` | **비밀번호는 저장하지 않는다.** 이름 최대 20자 |
| `qb:ui:v1` | `{sidebar, subject}` | 사이드바 접힘, 선택한 과목 탭 |
| `qb:theme` | `light` 또는 `dark` | 없으면 시스템 설정 |
| `qb:<bankId>:v1` | §5의 `S` | 형식 변경 없음. 대시보드 수치는 여기서 계산 |

`window.QB` API: `user()` · `login({name,email,provider})` · `logout()` · `rename(name)` · `safeNext(n)` · `requireUser(next)` · `theme.get/apply/toggle()` · `ui.get/set(patch)` · `SUBJECTS`.
- `safeNext`는 `dashboard.html` 또는 `dashboard.html#영숫자/=&_-` 형태만 통과시키고 나머지는 `dashboard.html`로 바꾼다(open redirect 방지).
- 로그아웃은 `qb:user`만 지운다. 진행 기록은 남는다.
- **mock 로그인은 UX용이다.** 서버 검증이 없어 localStorage를 고치면 누구나 로그인 상태가 된다. 보안 기능으로 쓰지 않는다. 문제은행 페이지는 로그인 검사를 하지 않고, 은행의 `S.name`이 비어 있을 때만 로그인 이름을 채운다.
- `qb-progress.js`(`QBP`): `snapshot / events / totals / xp / streak / heatmap / recent / continueList`. 모두 `tabs.at`·`wrong`·`board`에서 계산한다.

## 10. 음성 선택 (`design/qb-voice.js` → `window.QBVoice`)
API: `supported` · `canSpeak` · `parse(text,type,count)` · `attach(opts)` · `speak(text,lang)` · `cancelSpeak()` · `isSpeaking()` · `stopListening()`. `parse`는 순수 함수라 node로 테스트한다.
- 인식: `webkitSpeechRecognition`, ko-KR, 대안 5개. 마이크 버튼을 누를 때마다 한 번 듣는다.
- 받는 말: 숫자("2", "2번"), 한자어("이번", "삼"), 고유어("둘", "셋"), 서수("첫 번째"), 보기 글자("에이", "비", "a"), O/X("오·맞다·네" / "엑스·틀리다·아니"), 제출("제출·채점"). 번호는 화면 순서 기준이라 보기를 섞어도 맞는다. O/X 문제에서는 1번=O, 2번=X.
- multi 문제는 말할 때마다 선택이 켜지고 꺼진다. 게임 모드는 말하면 바로 선택하고 제출한다. 상태는 화면과 `aria-live`로 알린다. 권한 거부·네트워크 오류·음성 없음은 안내가 각각 다르다.
- '문제 읽기'는 `speechSynthesis`를 쓴다.
- **제약**: Chrome·Edge만 된다(미지원 브라우저는 마이크 버튼 숨김). 오디오가 브라우저 회사의 음성 서비스로 전송되므로 오프라인에서는 안 된다. `file://`에서는 마이크 권한을 다시 물을 수 있다. 듣는 동안에도 게임 타이머는 계속 흐른다.

## 11. 과목 확장
스키마에 선택 필드를 추가했다. 기존 79개 은행은 수정 없이 통과한다.
- 은행 `subject`: `it / korean / english / science / music / art / etc` (기본 `it`). 알 수 없는 값은 validate 오류.
- 문항 `img{src,alt[,caption]}`: 미술·과학 도해용. `src`와 `alt`가 필수다.
- 문항 `audio{src,transcript}`: 음악·영어 듣기용. `src`와 `transcript`가 필수다. 게임 모드는 오디오 문항을 건너뛴다.
- validate.py는 필드가 있을 때만 검사하고, quiz.html도 있을 때만 그린다.
- 대시보드 과목 탭(IT·국어·영어·과학·음악·미술): 은행이 있는 과목만 활성이고 나머지는 '준비 중'이다. 단계의 과목은 `build.py`의 `STAGE_SUBJECT`(지금은 전부 it)가 정한다.

## 12. PDF → 문제은행 자동화 로드맵
| 기능 | 지금 | 다음 단계 |
|---|---|---|
| 스캔 PDF·이미지 OCR | 없음. `ingest.py`는 글자 층만 추출하고 스캔본이면 경고만 낸다 | OCR 엔진을 ingest 앞단에 붙이고 쪽 번호를 유지해 `h.src`와 맞춘다 |
| 이미지 추출 | 없음. 문항 `img`는 사람이 경로를 넣는다 | PDF 도해를 잘라 저장하고 alt 초안을 만든 뒤 사람이 검수 |
| 자동 출제 | Claude Code에 출제 프롬프트를 주는 수동 작업 | `generate.py`(§6): ingest md → API → JSON → validate 실패 시 재시도 |
| 업로드 | 대시보드 `#upload`는 데모. 파일 이름만 보이고 내용은 읽지 않는다 | 서버에서 ①~⑤를 실행하고 내 문제은행 목록을 돌려주는 웹앱 |

랜딩 주장 C6~C9(음성 선택·PDF 자동 출제·OCR·타과목 은행)는 기능이 출시되고 확인될 때까지 claims.md에서 '보류'를 유지하고, 화면에는 '준비 중'으로만 표시한다. 음성(C6)은 구현됐지만 실제 브라우저 확인 뒤에 '검증'으로 바꾼다.

## 13. 알려진 후속 과제
- `quiz.html`에는 이모지, mono 숫자, 다크 모드의 이중 강조색(틸+앰버)이 남아 있다. 이번에는 고치지 않았고 정리 목록으로 둔다.
- 카탈로그 부제에 "A → B" 형태의 문자열이 있어 대시보드에 그대로 보인다. 부제를 고치거나 표시 규칙을 정한다.
- 같은 탭을 다시 채점하면 저장이 덮어써져(`tabs.at`은 마지막 채점 시각만 보관) 히트맵에는 한 번으로 센다.
- 타임어택에서 음성 인식에 걸린 시간만큼 제한 시간을 보정하는 기능은 아직 없다.
